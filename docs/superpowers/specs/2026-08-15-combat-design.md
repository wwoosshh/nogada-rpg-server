# 전투 설계 (아크 C) — 결정론적 패턴 실시간

**한 문장:** 몬스터는 시각의 함수로 움직이고, 플레이어는 몸으로 피하며, 서버는 행동의
순간만 판정한다 — 턴도 틱도 없고, 웹소켓도 없다.

## 0. 원작과 두 결정

**원작의 전투는 RPG Maker 기본 턴제였다**(사용자 증언 — 발굴 덤프가 소실돼 유일한
출처다). 즉 전투는 이 게임에서 **원작에 보존할 정체성이 없는 유일한 시스템**이고,
사용자가 정확히 그 이유로 차별화 지점으로 골랐다: "쯔꾸르 실시간은 틱을 둬서 사실상
턴제나 다름없다 — 최대한 자유롭고 실시간적으로."

사용자 결정 둘:
1. **판정 구조 = 결정론적 패턴 실시간** (풀 서버 시뮬·클라 판정+상한 검증을 제치고)
2. **전투의 산출 = 전투 전용 드랍 → 무기·방어구 사슬** (채집 문법 그대로)

## 1. 왜 — 이 게임에 위험이 0이다

아크 B 리뷰가 기록했다: "우리에겐 위험이 없다(전투가 없다)." 지금 게임의 모든 손실은
시간이고, 모든 선택은 수익률이다. 전투가 더하는 것은 **몸으로 감수하는 위험**이라는
새 축이다 — 그리고 그 위험이 노가다 게임의 결에 맞으려면, 위험은 잡히는 것이 아니라
**더 캐려는 욕심**에서 와야 한다(아래 §3).

경제 쪽 구멍도 하나 멘다: 골드는 들어오기만 하고 나갈 곳이 상점 증표뿐이다.
전투가 골드 소비처(여관 회복, §6)를 처음으로 낸다.

## 2. 판정 구조 — 이미 있는 기계 둘을 잇는다

### 2-1. 몬스터는 시각의 순수 함수다

`npcStateAt`(npcSchedule.ts)이 선례다 — NPC 는 서버 상태 없이 시각에서 위치가
유도된다. 몬스터도 같다: **`monsterStateAt(def, tMs)` 가 순찰 위치·예고 중인 공격·
위험 구역을 돌려주는 `packages/shared` 의 순수 함수**다. 클라이언트는 60fps 로
그리고, 서버는 판정 순간에 같은 함수를 불러 같은 답을 얻는다. 시계는 이미 동기화돼
있다(WT-4, 결계의 물때 판정이 이 동기화 위에서 이미 돈다).

틱 루프 없음 · 웹소켓 없음 · 몬스터 AI 저장 상태 없음.

### 2-2. 공격은 채집의 리듬이다

`POST /api/fight { instanceId, x, y }` — 노드 대신 몬스터, 나머지는 채집과 같은
기계다. `nextActionAt` 스탬프, 간격은 전투 숙련의 함수, 누르고 있으면 계속.
연속 채집이 이미 초당 7~8회 요청을 감당하므로 **새 부하 계층이 없다.**

서버가 한 요청에서 판정하는 것 셋:
1. **사거리** — 주장한 칸 (x,y) 가 몬스터의 현재 위치(§2-1 로 계산) 1칸 이내인가.
2. **명중** — 무기·전투 숙련으로 굴려 몬스터 HP 를 깎는다(HP 는 PlayerState 에,
   §5). 0 이 되면 드랍을 굴리고 처치 기록.
3. **피격** — 주장한 칸이 그 시각의 위험 구역 안인가. 안이면 **플레이어가 맞는다.**
   위험 구역도 §2-1 의 같은 함수가 준다.

### 2-3. 위치 주장과 개연성 — 치터의 상한 = 완벽한 플레이어

서버는 걸음마다 위치를 받지 않는다(이 저장소의 기존 설계 그대로). 전투 요청의
(x,y) 는 **주장**이고, 서버는 두 가지로 죈다:

- **속도 개연성**: 연속 주장 사이 거리 ≤ 경과시간 / `STEP_MS`(=200, shared 에
  있으므로 서버가 같은 상수로 잰다) + 여유 1칸.
- **결계 개연성**: 기존 `wrong_side` 기계가 이미 벽 너머 주장을 막는다.

이것이 주는 보안 성질을 정직하게 적는다: **치터가 얻을 수 있는 최대치는 완벽한
플레이어가 얻는 것과 같다.** 위치를 속여도 속도 한도 안에서 최적 칸을 고르는 것
이상은 못 하고, 그것은 손이 빠른 사람이 정당하게 하는 플레이와 같다. 채집이 이미
정확히 이 성질이다(봇이 A 를 완벽히 눌러도 간격 기계 이상은 못 얻는다). 서버 권위
규범은 예외 없이 유지된다 — **모든 굴림은 서버에서** 일어난다.

### 2-4. 서버는 행동의 순간만 안다 — 정직한 한계 둘

1. **가만히 서서 맞는 것은 없다.** 위험 구역에 서 있어도 행동하지 않으면 서버는
   모른다. 그래서 피해는 언제나 **공격하다가** 받는다 — 욕심의 대가이지 방치의
   벌이 아니다. 노가다 게임에서 이것은 결함이 아니라 결이다: 싸움은 네가 싸우는
   동안만 존재한다.
2. **몬스터는 쫓아오지 못한다.** 움직임이 시각의 함수라 플레이어 위치에 반응할 수
   없다. 몬스터는 자리를 지키고 패턴으로 무는 쪽이다 — 도망은 언제나 가능하고,
   죽음은 "잡혔다"가 아니라 "버티다 실패했다"다. 쫓아오는 몬스터·공유 보스는
   풀 서버 시뮬(웹소켓+틱)의 몫이고 별도 아크다(§10). 이 아크의 콘텐츠(몬스터
   정의·드랍·무기 사다리)는 그때 그대로 옮겨 탄다.

### 2-5. 지연은 예고 창이 삼킨다

공격 판정 시각은 서버 도착 시각이다(클라 주장 아님). 지연이 판정을 RTT 만큼 미는데,
예고 창을 그보다 훨씬 크게 잡아 삼킨다: 이동이 200ms/칸이고 모바일 반응이 ~300ms
이므로 **예고는 최소 700ms** — 한 칸 피하기(500ms)가 편하고, RTT(~50–200ms)는
그 안에서 소음이 된다.

## 3. 첫 콘텐츠 — 작게, 하나로 관통

노드 아크의 교훈(얼음 하나로 관통 → 나머지가 따라온다)을 그대로 쓴다.

- **사냥터 하나**: 월드맵에 문 하나로 붙는 새 맵. 맵 저작은 고정 설계도 + 눈 승인
  (메모리 규범 — 절차 생성 금지).
- **몬스터 한 종: 들늑대** — 배치 셋. 패턴(전부 `monsterStateAt` 이 유도):
  - 순찰: 제자리 주변 몇 칸을 도는 고정 경로 (NPC_STEP_MS=400 재사용 — 플레이어
    절반 속도라 접근이 쉽다).
  - 공격: 주기적으로 **전방 부채꼴 3칸 예고(바닥 표시) 후 휩쓸기.** 예고 ≥700ms.
  - 처치 시: 그 플레이어에게만 쓰러진 상태(리스폰 대기 시간도 시각 유도 —
    처치 시각 + N 이 PlayerState 에 있으므로 계산 가능).
- **드랍 한 종: 늑대 송곳니** — 확률표는 채집표와 같은 모양(누적 확률, 서버 전용).
- **무기 사다리 시작: 구리 검** — `구리 주괴 + 늑대 송곳니 N`. 제작 루프·계열 탭·
  자동 착용 전부 재사용. 무기는 `kind=tool`, 슬롯은 `'combat'`(`equipped` 가 열린
  레코드라 스키마 무변경). 검이 올리는 것은 **회당 피해** 하나다 — 간격은 숙련이,
  피해는 무기가(도구 사다리에서 배운 "한 칸이 두 축을 사면 안 된다").

죽은 재료 구제·방어구·상위 무기·몬스터 추가는 전부 다음 아크다(§10).

## 4. 전투 숙련과 간격 — 50ms 교훈을 미리 적용한다

전투 숙련은 **`skills` 에 넣지 않는다.** `skills` 는 `.strict()` 라 키 추가가 곧
세이브 마이그레이션인데, `donated`·`weather`·`lastTalkAt` 이 증명한 길이 있다 —
**기본값 있는 새 최상위 필드는 마이그레이션 0** 이다. `combat` 필드 하나에 숙련·HP·
사냥 진행을 묶고 `.default()` 를 준다. 이정표의 `skill` 지표 기계는 안 건드린다
(전투 이정표는 다음 아크).

공격 간격은 채집의 로그 곡선을 재사용하되 **자체 상수**를 둔다:
`COMBAT_INTERVAL_MAX_MS = 800`, **`COMBAT_INTERVAL_MIN_MS = 400`**. 하한을 높게
잡는 이유는 아크 B 가 재서 배운 것이다 — 채집의 50ms 하한이 4단 도구의 간격 이득을
숙련 600,000 에서 0% 로 삼켰다. 전투는 하한을 애초에 리듬(예고 700ms 와 견주어
의미 있는 크기)에 맞춰 두고, 숙련의 이득 폭도 ×2 로 유한함을 처음부터 문서가 안다.
숙련 증가는 채집과 같은 문법: 성패 무관 회당 +1~2.

## 5. 상태 — 전부 PlayerState 에, 전부 게으르게

```
combat: {
  proficiency: number          // 전투 숙련
  hp: number                   // 현재 HP (max 는 상수 100 으로 시작)
  lastHitAt: number            // 마지막 피격 시각 — 자연 회복을 게으르게 계산
  hunt: { instanceId, monsterHp, slainAt? } | null   // 진행 중인 사냥 하나
}
```

- **몬스터 HP 는 플레이어별이다** — 채집 노드가 플레이어별인 것과 같고, 오늘 다른
  플레이어가 존재하지 않으므로(presence 는 NPC 전용, 리뷰 실측) 공유할 대상도 없다.
- **자연 회복은 틱이 없다**: `lastHitAt` 에서 경과 시간 × 회복률로 판정 순간에
  계산한다. 날씨 만료(`untilMs` 비교 하나)와 같은 자세다.
- **죽음**: HP 0 → 마을 스폰으로 귀환, 진행 중 사냥 리셋. **소지품·골드 무손실** —
  이 게임의 화폐는 시간이고, 죽음의 대가도 시간이다(돌아가는 길 + 사냥 처음부터).
- **여관 회복**: 여관안주인(눈의마을 9,14 — 이미 화자로 실재)이 골드를 받고 HP 를
  채운다. 골드가 나가는 첫 문이다. 자연 회복은 공짜지만 느리게 — 둘의 비는 구현
  중에 재고 정한다.

## 6. 화면 — 있는 문법 재사용

- **A 버튼 문맥 확장**: 앞이 노드면 채집(지금), 몬스터 사거리 안이면 공격. 새 버튼 없음.
- **예고는 바닥 표시**: 위험 구역을 바닥 타일 위에 그린다(반투명 붉은 칸). 몬스터
  피격·플레이어 피격은 FloatingText 재사용.
- **HP 바**: 상단 바에 플레이어 HP, 몬스터 위에 몬스터 HP. 도감·제작 패널 무변경.
- 죽었을 때: 결계 밀림과 같은 문법으로 화면이 말한다("쓰러졌다 — 마을로 돌아간다").

## 7. 검증 — 풀 수 있는 패턴만 출하된다

빌드 시 `monsterStateAt` 을 전 주기 시뮬해서 무는 검사 셋(결계의 함정 방지 검사와
같은 자세 — 규범마다 무는 검사를 같은 태스크에서):

1. **피할 수 없는 순간이 없다** — 모든 시각 t 에 대해, 위험 구역 밖이면서 도달
   가능한(STEP_MS 예산 안) 칸이 존재한다.
2. **영원히 안전한 공격 칸이 없다** — 사거리 안이면서 전 주기 내내 위험 구역 밖인
   칸이 존재하면 위반. 있으면 전투가 "자리 잡고 A 홀드"로 퇴화해 채집과 같아진다.
3. **예고가 충분하다** — 모든 공격의 예고 시작→명중이 ≥700ms.

셋 다 결정론이라 100% 재현 가능하고, 패턴 데이터(CSV)를 고치는 작가가 빌드에서
바로 듣는다. 시계 결정론 테스트도 하나: 같은 t 에 클라 렌더와 서버 판정이 같은
상태를 본다(`monsterStateAt` 쌍방 호출 대조).

## 8. 성공 기준

1. 브라우저(812×375)에서: 예고를 보고 **발로 피하고**, 안전한 순간에 때려서 잡고,
   드랍을 받고, 구리 검을 만들어 자동 착용되고, 회당 피해가 오르는 것을 **DOM 으로**
   확인한다.
2. 위험 구역 안에서 공격하면 서버가 피격을 판정한다 — 클라이언트 표시가 아니라
   HP 가 실제로 깎인 것을 상태로 확인.
3. 속도 개연성 검사가 문다: 순간이동 주장(전 주장에서 10칸/100ms)이 거절된다.
4. §7 의 검사 셋이 출하 패턴에서 초록이고, 각각 위반 픽스처에서 빨개진다(돌연변이).
5. 죽음 → 마을 귀환 → 사냥 리셋이 저장 상태로 확인된다.
6. 구세이브(combat 필드 없음)가 그대로 로드된다 — 마이그레이션 0 의 증명.
7. `pnpm test` 초록.

## 9. 열려 있는 위험

- **AFK 무피해 모델의 체감** — "서 있는데 장판을 맞지 않는다"가 화면에서 이상하게
  보일 수 있다. 클라이언트가 장판 명중을 연출로만 보여주는 것은 거짓말이므로 하지
  않는다 — 장판은 "다음 행동이 위험한 자리" 표시로 그린다. 구현 중 브라우저에서
  체감을 재고, 어색하면 §2-4 의 결정을 재검토한다.
- **몬스터 HP 가 사냥 하나뿐** — `hunt` 가 단수라 동시에 한 마리만 상대한다.
  단순화 결정이고, 여럿이 필요해지면 다음 아크가 배열로 늘린다.
- **모든 시간 수치는 목표값**이다 — 예고 700ms·간격 800→400ms·회복률은 구현 중
  브라우저에서 재고 확정한다(가루 저울과 같은 절차, 이번엔 결정 기록을 남긴다).
- **밤·날씨와의 상호작용 없음** — 사냥터는 조건 없이 열린다. 특수 노드가 이미 그
  축을 쓰므로 전투까지 겹치면 축이 섞인다.

## 10. 범위 밖

- **풀 서버 시뮬(웹소켓 + 틱)** — 쫓아오는 몬스터·공유 보스·협동. 이 아크의 데이터
  모델이 그대로 옮겨 탈 수 있게 몬스터 정의를 CSV 에 둔다.
- 방어구 · 상위 무기(철·미스릴·별똥 검) · 몬스터 추가 · 원거리 무기
- 전투 이정표 · 전투 칭호 · 도감의 전투 페이지

## 11. 스펙 자체 점검에서 이미 아는 약점

이 스펙은 초안이다. 3렌즈 평가 전에 스스로 아는 것:

- §7 검사 1·2 는 "칸이 존재한다"인데 **도달 가능성**(그 순간 플레이어가 실제로 그
  칸까지 갈 수 있는가)은 시작 위치에 의존한다 — 검사의 정확한 술어는 평가가 다듬어야
  한다.
- 무기 피해·늑대 HP·드랍 확률·송곳니 수요의 목표 숫자를 아직 안 정했다 — 노드
  아크의 §5 처럼 "분으로 재는 자"부터 정해야 한다(첫 검 획득까지 N분).
- `hunt.slainAt` 리스폰과 몬스터 순찰 주기의 위상(리스폰 직후 어떤 패턴 상태인가)을
  안 정했다.
