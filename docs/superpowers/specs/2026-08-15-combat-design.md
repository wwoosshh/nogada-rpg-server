# 전투 설계 (아크 C) — 결정론적 패턴 실시간

**한 문장:** 몬스터는 시각의 함수로 움직이고, 플레이어는 몸으로 피하며, 서버는 행동의
순간만 판정한다 — 턴도 틱도 없고, 웹소켓도 없다.

> **이 문서는 3렌즈 평가를 한 번 받고 다시 쓴 것이다.** 평가가 치명 셋(위험 창의 이중
> 읽기 · 획득 그물이 전투 드랍에서 빌드를 깨뜨림 · 시계 오차가 예고 창을 삼킴)과
> 틀린 사실 여덟을 잡았다. 살아남은 규범 26개는 §12-앞 에 있고 **그 절이 다른 모든
> 절보다 우선한다.**

## 0. 원작과 결정 넷

**원작의 전투는 RPG Maker 기본 턴제였다**(사용자 증언 — 덤프 소실로 유일한 출처).
전투는 원작에 보존할 정체성이 없는 유일한 시스템이고, 사용자가 그 이유로 차별화
지점으로 골랐다.

사용자 결정 넷:
1. **판정 구조 = 결정론적 패턴 실시간** (웹소켓·틱 없음)
2. **산출 = 전투 전용 드랍 → 무기 사슬**
3. **위험 창 = 휩쓸리는 동안** — 예고 중에는 그 자리에서 공격해도 무사하고, 휩쓸기가
   시작되면 그 칸의 공격은 확정 피격이다. 마지막 순간까지 한 대 더 때리는 탐욕의
   긴장이 살고, 회피를 안 하면 휩쓸기마다 맞아 **35초에 죽는다**(실측 산술) —
   회피가 의무가 되어 전투가 전투답다.
4. **공격 홀드는 처음부터 연다** — 채집의 홀드 해금(숙련 10,000)이 하던 일(초반에
   손을 붙잡아 두기)을 전투에서는 회피 축이 대신한다. 홀드 잠금까지 겹치면 이중
   세금이고, 기술적으로도 이정표 repeat 지표가 전투 숙련을 못 받는다(§12-앞 20).

## 1. 왜 — 이 게임에 위험이 0이다

지금 게임의 모든 손실은 시간이고 모든 선택은 수익률이다. 전투가 더하는 것은 **몸으로
감수하는 위험**이라는 새 축이고, 그 위험은 잡히는 것이 아니라 **더 때리려는 욕심**에서
온다(결정 3).

여관 회복의 "왜"를 정확히 적는다: 골드 싱크는 이미 있다 — 강화가 최대 싱크이고
(`enhance_costs.csv` 5,000→960,000, `not_enough_gold` 검사 실재) 재료 되사기도 있다.
여관이 새로 파는 것은 **죽음 비용을 시간에서 골드로 바꾸는 선택지**다. 자연 회복은
공짜지만 느리고, 여관은 즉시지만 골드를 받는다.

## 2. 판정 구조

### 2-1. 몬스터는 시각의 순수 함수다

`npcStateAt`(npcSchedule.ts)이 선례다. **`monsterStateAt(def, tMs)`** 가 순찰 위치·
걸음 진행도·현재 공격 국면(대기/예고/휩쓸기)·위험 구역을 돌려주는 `packages/shared`
의 순수 함수다. 클라이언트는 그리고, 서버는 판정 순간에 같은 함수를 부른다.

- **패턴은 단일 주기다**(§12-앞 19) — 여러 주기의 합성이면 lcm 이 검증 시뮬의 길이를
  못박지 못한다. 패턴 CSV 는 한 주기를 적고 함수가 `t mod P` 로 돈다.
- **걸음 진행도를 노출한다**(§12-앞 16) — 클라 렌더가 NpcSprite 의 추격 보간을 쓰면
  화면 몬스터가 수학 위치보다 정상 상태 0~1칸 뒤진다(추격 속도 = 목표 속도, 실측).
  몬스터 스프라이트는 `monsterStateAt` 의 진행도로 직접 보간해 그린다.

### 2-2. 공격은 채집의 리듬이다

`POST /api/fight { instanceId, x, y }` — `nextActionAt` 스탬프, 간격은 전투 숙련의
함수, 홀드로 계속.

- **`nextActionAt` 은 채집과 공유한다**(§12-앞 17) — 같은 기계 = 같은 필드다. 전투와
  채집을 번갈아 눌러 배속하는 악용이 원리적으로 불가능한 것이 이 공유의 뜻이고,
  그것을 무는 검사를 §8 에 둔다.
- **명중 굴림은 없다**(정정 2). 사거리 안이면 맞는다 — 채집에서 성공률 곡선을
  은퇴시킨 결정과 같은 자리다. 간격은 숙련이, 회당 피해는 무기가 진다(한 칸이 두 축을
  사면 안 된다).
- 서버가 한 요청에서 판정하는 것: ① 사거리(주장 칸이 몬스터 현재 칸에서 맨해튼
  1 이내) ② 몬스터 HP 감소·처치·드랍 ③ **피격** — 주장 칸이 휩쓸기 활성 구역
  안이면 플레이어 HP 감소.
- **피격·처치·죽음은 전부 `ok:true` outcome 에 실린다**(§12-앞 14) —
  `applyToCharacter` 가 `ok:false` 를 저장하지 않으므로 거절 경로에서는 아무것도
  판정하지 않는다. 귀결: 피해 빈도의 상한은 **수락된 스윙당 1회**다(too_fast 연타는
  무피해 — 수락된 스윙이 어차피 오므로 악용이 아니다. 늑대 피해 수치는 이 상한
  위에서 잰다). 한 요청이 처치와 죽음을 같이 내면 **처치가 먼저다** — 드랍과 처치
  기록이 실리고 나서 귀환한다(잡고 죽은 사람이 빈손이면 안 된다).

### 2-3. 위치 주장과 개연성

서버는 걸음마다 위치를 받지 않는다(기존 설계). 전투 요청의 (x,y) 는 주장이고:

- **거리는 맨해튼이다**(§12-앞 6). 이동이 4방향이므로 — 체비쇼프로 재면 대각 주장이
  정직한 걸음의 2배속으로 통과한다(실측: 대각 5칸 = 맨해튼 10칸 = 정직 2,000ms 를
  체비쇼프 5 는 800ms 로 통과시킨다).
- **속도 개연성**: 직전 주장(`combat.lastClaim`, §6)과의 맨해튼 거리 ≤ 경과시간 /
  `STEP_MS` + 여유. 여유 상수는 지터를 재서 정한다(§12-앞 18 — 최대속도 이동 중
  최소간격 공격은 지터 압축 200ms 부터 정당한 요청이 거절되므로, 여유가 그보다 커야
  한다).
- **첫 주장·전환 직후는 검사가 공회전한다 — 의도다**(§12-앞 7). "그동안 걸어간 것과
  등가"라 위협 모델 안에서 무해하고, 이 저장소가 이동·채집에서 이미 명문으로 수용한
  노출 클래스다(`moveService.ts:44-47`).
- **벽 칸 주장은 막지 못한다 — 수용한다**(§12-앞 5). 지형은 서버로 안 넘어오고
  (`types.ts` MapDef 주석), 결계 구역 기계는 게이트 문 뒤만 안다 — 사냥터는 조건
  없이 열리므로 결계 구역이 없다. 벽 치터의 이득은 벽 관통 최단 경로 = 상수 여유급이고,
  §8 검사 2 의 정의역을 전체 칸으로 두면 "벽 속 영원 안전 칸"도 검사가 문다.
- 보안 문장의 정확한 형태(§12-앞 15): **치터의 상한 = 완벽한 플레이어 + 상수 여유**
  (여유 1칸 + 벽 관통 경로). 모든 굴림은 서버에서 일어난다는 것은 변함없다.

### 2-4. 서버는 행동의 순간만 안다 — 정직한 한계 둘

1. **가만히 서서 맞는 것은 없다.** 피해는 언제나 공격하다가 받는다 — 욕심의 대가이지
   방치의 벌이 아니다. 화면의 장판은 "지금 여기서 공격하면 맞는 자리" 표시다(§7).
2. **몬스터는 쫓아오지 못한다.** 도망은 언제나 가능하고 죽음은 "버티다 실패했다"다.
   쫓아오는 몬스터·공유 보스는 웹소켓 아크의 몫(§11).

### 2-5. 판정 시각 — RTT 만이 아니라 시계 오차까지

판정 시각은 서버 도착 시각이다. 클라와 서버가 갈라지는 폭은 **RTT + 시계 동기화
오차 + slew 빚**이고, 마지막 둘이 크다(§12-앞 3, 전부 실측):

- 동기화는 어긋남 2,000ms 초과에만 재동기한다(`RESYNC_THRESHOLD_MS`) — ±2초가 상시
  용인된다. RTT 스파이크 중 잡힌 앵커는 ~1초 오차를 만들고 백스톱에 안 걸려 다음
  주기 동기(5분)까지 지속된다. 1초 > 예고 700ms.
- 저장소 스스로 이 부류를 관측했다(`NpcSprite.ts:28-29` "시계 재동기가 한 칸쯤
  앞당길 수 있어서").

**완화 = 판정 시간 허용폭.** 사거리·피격 판정을 t 한 점이 아니라 **t±ε 구간에서
하나라도 성립하면 인정**으로 한다(ε 는 오차 상한에서 유도, 구현 때 상수로 못박고
왜를 적는다). 5분 지속 오차까지 삼키는 가장 싼 완화다. §8 의 결정론 테스트는 같은
t 를 넣는 한 이 결함을 못 무므로 **오차 주입 테스트**(앵커 ±1초 어긋냄)를 같이 짠다.

## 3. 위험 창 — 휩쓸리는 동안 (결정 3)

한 공격의 생애: **대기 → 예고(바닥 표시, ≥700ms) → 휩쓸기(활성, 수백 ms) → 대기**.

- 예고 중: 그 칸에서 공격해도 무사. 마지막까지 때리는 것이 옳은 플레이다.
- 휩쓸기 중: 그 칸에서의 공격 = 확정 피격. 한 칸 옆(200ms)이면 무사.
- **"회피 안 하는 사람은 휩쓸기마다 맞는다"를 빌드 검사로 못박는다**(§12-앞 1) —
  A 홀드 방치자의 휩쓸기당 기대 피격 ≥ 1. 이 검사가 활성 창의 하한을 지킨다(창이
  공격 간격보다 좁으면 방치자가 우연히 안 맞는 휩쓸기가 생긴다 — 그래서 활성 창 ≥
  공격 간격 하한 400ms).

## 4. 첫 콘텐츠 — 작게, 하나로 관통

- **사냥터 하나**: 월드맵에 문 하나로 붙는 새 맵. 맵 저작은 고정 설계도 + 눈 승인.
- **들늑대 한 종, 배치 셋** — 패턴은 전부 `monsterStateAt`:
  - 순찰: 제자리 주변 고정 경로(NPC_STEP_MS=400 재사용).
  - 공격: 전방 부채꼴 3칸, 예고 ≥700ms → 휩쓸기.
  - **배치 셋은 패턴 위상이 서로 다르다**(§12-앞 23) — 위상까지 같으면 한 마리를
    세 번 잡는 것과 같다.
  - 처치 기록은 `hunt` 밖에 둔다(§12-앞 11): `combat.slain: Record<instanceId, atMs>`.
    hunt 단수에 처치 시각을 실으면 다른 늑대와 교전하는 순간 기록이 사라져 리스폰
    대기가 무효가 된다. hunt 교체(다른 몬스터 공격) 시 이전 몬스터의 HP 는 만혈로
    돌아간다 — 한 번에 하나를 상대하는 단순화의 값이고 §9 에 명시한다.
- **드랍: 늑대 송곳니** — 확률표는 채집표 모양(서버 전용).
  - **획득 그물 확장이 선행 태스크다**(§12-앞 2): `validate.ts` 의 획득 검사
    ("채집으로도 제작으로도 구매로도 획득할 수 없다")가 전투 드랍을 몰라 **지금 이
    데이터는 빌드가 죽는다**(재현됨). 검사에 "전투 드랍" 출처를 가르치고, 확장 후
    "드랍 출처 없는 아이템" 위반 픽스처를 돌연변이로 둔다.
  - **송곳니 잉여는 강화가 닫는다**: 구리 검은 강화 가능한 도구이고, 강화 +1 은 같은
    검 한 자루를 재료로 먹는 기존 기계(`performEnhance`) 그대로다 — 착용 1 + 강화
    +5 = **검 6자루분의 송곳니 반복 수요**가 새 기계 0개로 성립한다. 도구 사다리와
    같은 모양이다.
- **무기: 구리 검** — `구리 주괴 + 늑대 송곳니 N`. 회당 피해 하나만 올린다.
  - **첫 늑대는 구조적으로 맨손이다**(§12-앞 9) — 송곳니가 검의 재료이므로.
    **맨손 전투 피해 상수**를 둔다(채집의 `BARE_HAND` 대응).
  - **슬롯 타이핑 분리**(§12-앞 8): "스키마 무변경"은 세이브 zod 게이트에서만 참이다.
    `toolSkill=combat` 인 items.csv 행은 **현행 파서가 거절한다**(SKILL_IDS 검증,
    재현됨). `SKILL_IDS` 에 combat 을 넣는 길은 함정이다 — `skillsShape` 가 거기서
    생성되고 `.strict()`+필수라 **구세이브가 깨진다(재현됨)**. 안전 경로: SKILL_IDS·
    세이브 스키마 불변, `EquipSlot = SkillId | 'combat'` 타입 신설, 파서 분기 확장,
    `equipService`·`craftService` 의 슬롯 결정 수정, `validate.ts` 의 "기술별 1티어
    도구 정확히 하나" 검사가 combat 을 건너뛰게. 전부 빌드타임이라 구세이브 무해.
  - 자동 착용은 `isBetterTool` 의 축 분기(기술마다 다른 축 — 기존 주석이 명문화)에
    피해 축을 더한다.

## 5. 숙련과 간격

전투 숙련은 `skills` 가 아니라 `combat` 필드에 산다(§6 — 기본값 = 마이그레이션 0.
`skills` 는 `.strict()` 라 키 추가가 곧 구세이브 거절이다, 재현됨).

간격은 로그 곡선 재사용 + 자체 상수: `COMBAT_INTERVAL_MAX_MS = 800`,
`COMBAT_INTERVAL_MIN_MS = 400`. 하한을 높게 잡는 이유는 아크 B 의 50ms 교훈이고,
§3 의 "활성 창 ≥ 400ms" 하한과 맞물려 방치자 기대 피격 ≥ 1 이 성립한다.
숙련 증가는 성패 무관 회당 +1~2. 홀드는 처음부터(결정 4).

## 6. 상태 — 전부 PlayerState 에, 전부 게으르게

```
combat: {
  proficiency: number
  hp: number                       // max 는 상수 100 으로 시작
  lastHitAt: number                // 자연 회복을 게으르게 계산
  lastClaim: { x, y, atMs } | null // 속도 개연성의 재료 (§2-3) — 없으면 검사 구현 불가
  hunt: { instanceId, monsterHp } | null
  slain: Record<instanceId, atMs>  // 처치 기록 — hunt 밖 (§4)
}
```

- 전부 `.default()` 라 **구세이브 마이그레이션 0** (`donated` 가 증명한 길 —
  정확히는 중첩 `.default({})` 인 `dialogueHistory.lastTalkAt` 이 같은 모양이다).
- **`currentHp(combat, now)` 술어를 shared 에 하나** 둔다(§12-앞 14) — 서버 판정과
  TopBar 표시가 같은 함수를 부른다(transitionGate·nodeAvailable 규범).

- **여관 회복**: 즉시, 골드. 자연 회복 대비 가격을 **부등식으로** 적는다: 여관비 ≤
  (자연 회복 대기 시간에 그 플레이어가 벌 수 있는 골드) — 아니면 아무도 안 산다.
  구체값은 구현 중 브라우저에서 재고 **결정을 기록한다**(가루 저울의 교훈).

  밤 죽음 직후엔 자연 회복뿐이라는 동선을 §9 위험에 적는다(§12-앞 25).

## 7. 화면

- **A 버튼 술어 변경을 명문화한다**(§12-앞 21): 현행은 앞칸 고정
  (`interactableAt(frontTile)`), 전투는 **사거리 안**(맨해튼 1)이다. 노드와 몬스터가
  동시에 조건을 만족하면 **앞칸(노드)이 우선** — 채집 조작이 기존과 한 톨도 안
  달라지는 쪽을 고른다.
- 장판(위험 구역)은 바닥에 그린다 — 예고는 옅게, 휩쓸기(활성)는 진하게. 뜻은 "지금
  여기서 공격하면 맞는다"다(§2-4).
- 몬스터 렌더는 `monsterStateAt` 진행도 직접 보간(§2-1). HP 바: 상단에 플레이어,
  몬스터 위에 몬스터. 죽음은 결계 문법으로 화면이 말한다.

## 8. 검증 — 풀 수 있는 패턴만 출하된다

빌드 시 `monsterStateAt` 전 주기 시뮬(단일 주기라 유계):

1. **피할 수 없는 순간이 없다** — 술어는 **생존 가능 핵의 최대 고정점**(평가 채택
   권고): 명중 순간 h₁<…<h_k 에 대해 S(i) = { 걷는 칸 p : p ∉ danger(h_i) ∧ ∃q,
   맨해튼(p,q) ≤ ⌊(h_{i+1}−h_i)/STEP_MS⌋ ∧ q ∈ S(i+1) } 를 고정점까지 줄이고,
   모든 걷는 칸·모든 예고에서 예산 안에 S 로 들어갈 수 있어야 한다. 피해가 명중
   순간에만 존재하므로 명중 시각만 검사하면 충분하다. **정의역: 걷는 칸.**
2. **영원히 안전한 공격 칸이 없다 — 시간 축 포함**(§12-앞 4·5): 전 주기 내내 안전한
   칸(공간 퇴화)만이 아니라 **연속 안전 시간의 상한**도 죈다 — 안 그러면 "주기의
   95%가 안전한 칸 + A 홀드"가 통과한다(측면 한 칸 200ms 가 A 놓기 700ms 보다 싸다).
   **정의역: 전체 칸**(벽 포함 — 벽 치터의 A 홀드 칸을 여기서 문다).
3. **예고 ≥ 700ms**, **활성 창 ≥ 400ms**, **방치자 휩쓸기당 기대 피격 ≥ 1**(§3).
4. **배치 유효성**(§12-앞 22): 몬스터 배치 칸·순찰 경로가 걷는 칸 위인가.
5. **오차 주입**(§2-5): 앵커 ±1초 어긋난 두 시계로 클라 상태와 서버 판정을 대조 —
   허용폭 ε 가 실제로 삼키는지.
6. **번갈아 악용**(§12-앞 17): 채집→전투→채집 연타가 단독 연타보다 빠르지 않다.
