# 채집 구체화 설계 — 티어 분포가 숙련의 함수다

**날짜:** 2026-08-12
**상태:** 깨끗한 세션 평가 3렌즈(밸런스·원작 충실 / 아키텍처 / 데이터) 반영 완료 — §7-앞이 규범
**사용자 요구:** 채집을 더 구체화하라. 광물은 어느 정도 됐지만 얼음·나무·허브는 단계도
채집물 종류도 없다. 원작을 확인하라.

**원작 발굴 결과(스크립트·커먼이벤트·아이템 데이터 원본에서 복원 — 근거 덤프는
분석용 스크래치패드 `original-scripts/`, `prob_261~264.txt`, `original-items.md`):**

- 판정: 조사 1회 = `roll = rand(0..100000)` 1회. **숙련 브라켓**(500 / 5,000 /
  10,000 / 150,000 / 500,000 / 그 이상; 나무만 30k·70k·290k가 끼어 8브라켓)마다
  티어별 **누적 확률표**가 통째로 바뀐다. 성공률이 아니라 **무엇이 나오는가**가
  숙련의 함수다.
- 최상 티어는 숙련 0부터 0.003%로 상시 개방(잭팟). 최종 브라켓은 실패 0%.
- **실패해도 숙련 +1~2** — 성패 무관, 매 시도 지급.
- 티어 수: 얼음 5, 나무 6(+부산물), 허브 7, 광물 10.
- 도구(선별기 하/중/상)는 게이트가 아니라 **roll ×0.9~0.8 보정** — 낮은 roll일수록
  상위 티어이므로 곱이 작을수록 희귀 티어 확률이 체감 20~25% 오른다.
- 문턱은 숫자를 말한다: 거래 5,000 · 상점 확장 10,000 · 선별기 25,000 · 결계
  85,000 · 달인 63,235(비정형 — 소문으로만 발견) · 수집가의방 4종 각 5,000.
- 노드는 고갈·리스폰 없음. 광산의방 = 확정 재료 + 숙련 무증가(레벨링·파밍 분리).

---

## 1. 목표

네 채집장이 각자 5~7단의 채집물 사다리를 갖는다. 숙련이 오르면 같은 노드에서
새 재료가 **벽이 무너지듯** 쏟아지기 시작하고, 실패한 손질도 숙련을 쌓는다.
초보의 첫 채집에서도 아주 가끔 전설급이 터진다.

## 2. 판정 모델 교체 (packages/shared)

```
gatherOutcome(table, proficiency, toolFactor, rng)
  → { itemId: string | null, roll: number }   // null = 실패
```

- `roll = floor(rng() × 100001 × toolFactor)` → 현재 숙련 브라켓의 누적표에서
  첫 번째로 `roll ≤ 상한` 인 티어. 어디에도 안 걸리면 실패.
- **성패 무관 숙련 +[skillGainMin..skillGainMax]** (노드가 아니라 테이블이 소유).
- 기존 `calcGatherSuccess` 로그 곡선은 채집에서 은퇴한다(제작 성공률은 불변).
  행동 간격(`nextActionAt`, 숙련에 따라 500→50ms)은 그대로 — 원작의 Wait
  단축 사다리와 같은 역할을 이미 한다.
- 서버가 판정의 유일한 주인(기존 gatherService 개조). 클라이언트는 결과 표시만.

## 3. 데이터 모델

### 3.1 `gather_tables.csv` (신설) — 표가 진실이다

```
tableId,bracketMax,itemId,cumulative
ice,500,ice_gem,3
ice,500,pure_ice_crystal,8
ice,500,ice_crystal,18
ice,500,pure_ice,15018
ice,500,ice_shard,60000
ice,5000,...
```

- 한 줄 = (테이블, 브라켓, 티어) 의 누적 상한. 브라켓은 `proficiency ≤ bracketMax`
  로 고르고 마지막 브라켓은 `bracketMax = ∞`(빈 칸 또는 `max`).
- 수치는 **원작 표를 그대로 준용**하되 우리 아이템 수(§4)에 맞게 티어를 대응시킨다.
  원본 수치: 스크래치패드 `prob_261~264.txt` (구현 태스크가 참조).
- 검증(작가용 메시지): 브라켓 오름차순·중복 금지, 브라켓 안 누적 단조 증가·
  ≤100000, 티어 순서가 모든 브라켓에서 동일, 없는 아이템 금지, 마지막 브라켓
  실패 0% 는 **강제하지 않되 경고 없음**(의도), 첫 브라켓에 최상 티어 존재(잭팟
  보존)는 경고.

### 3.2 nodes.csv 개조 — 노드는 표를 가리킨다

- `yieldItem/yieldMin/yieldMax/baseChance/tier` → `tableId` 로 교체. 수량은 항상
  1(원작과 동일 — 수량 스케일링은 원작에 없다).
- **필드당 노드는 시각 변형 2종이 같은 표를 공유한다**(원작의 광물 4색 노드 =
  외형만 차이). 기존 심층 노드(tier 2)는 같은 표의 다른 외형이 된다 — 맵 수정
  불필요, 배치 그대로.

  > **정정(2026-08-13, 결계 아크 B2·B3): 더 이상 같은 표를 공유하지 않는다.**
  > "맵 수정 불필요" 를 산 대가가 무엇이었는지가 결계 설계의 계기 둘이다 —
  > 심층 노드 넷이 이름과 마커 색만 심층인 채 바깥과 **완전히 같은 분포**를
  > 굴렸고, 그 위에서 얼음안내판이 "구리 정으로는 안 깨진다"고 거짓말을 했다.
  > 지금은 `deep` 노드가 `*_deep` 표를 가리키고(분당 산출 ×2.5) 맵도 수정됐다
  > (네 채집장에 결계 구역). `variant` 와 `tableId` 가 다시 갈라지는 것은
  > 빌드가 막는다(결계 §9-앞 5).
- `skillGainMin/Max` 는 테이블로 이사(2.의 소유권).

### 3.3 도구 — 게이트에서 보정으로

- `canGather` 의 "그 기술의 도구 착용" 요구는 유지(도구가 기술 정체성이다).
  **노드 tier 게이트는 폐지**(노드에 tier 가 없어진다).
- `ItemDef.toolTier` → `gatherFactor` 환산: 구리(1티어) ×1.0, 철(2티어) ×0.9,
  미스릴(3티어, §4) ×0.8. shared 에 `toolGatherFactor(def)` 하나로.

## 4. 아이템 사다리 (자작 이름 — 원작 사다리 구조 준용)

기존 8종은 id·이름 유지(세이브 호환), 새 재료 14종 추가 → 채집물 총 22종.

| 스킬 | 사다리 (하→상, *=기존) |
|---|---|
| 얼음 (5) | *얼음 조각 → *맑은 얼음 → 얼음 결정 `ice_crystal` → 맑은 얼음 결정 `pure_ice_crystal` → 얼음의 보석 `ice_gem` |
| 나무 (6) | *무른 통나무 → 찻잎 `tea_leaf` → *단단한 통나무 → 금빛 잎 `golden_leaf` → 나무 열매 `tree_fruit` → 금빛 열매 `golden_fruit` |
| 허브 (7) | *흔한 약초 → 라벤더 `lavender` → 라임 `lime` → 세이지 `sage` → *귀한 약초 → 아로마 `aroma_herb` → 천년초 잎 `millennium_leaf` |
| 광물 (7) | *구리 원석 → *철 원석 → 은 원석 `silver_ore` → 사파이어 원석 `sapphire_ore` → 루비 원석 `ruby_ore` → 금 원석 `gold_ore` → 미스릴 원석 `mithril_ore` |

- 광물은 원작 10단을 당장 다 옮기지 않는다 — 7단이면 사다리 감각이 성립하고,
  황동·다이아 등은 콘텐츠 확장 여지로 남긴다(훅).
- 아이콘: 확보된 Time Fantasy 팩에서 14종 신규 배정. **컨트롤러가 대조 시트로
  직접 보고 승인**(기존 규칙). 기존 예비 아이콘(ore_mithril·ingot_mithril)이
  미스릴 계열에 정당한 주인을 얻는다. CREDITS 레시피·3중 유일성 테스트 확장.
- `kind` 는 전부 `material`. 원작의 회복/사용 효과는 소비 시스템이 없으므로 훅.

## 6. 문턱 — 숨은 사건 (기존 장치만으로)

- **브라켓 경계 자체가 암묵 문턱이다** — 15만을 넘는 순간 표가 바뀌어 어제 없던
  재료가 쏟아진다. 이것이 이 설계의 주된 "숨은 사건"이고, 어디에도 예고하지 않는다.
- 대사 문턱(각 채집장 화자, 기존 조건부 대사 장치): 숙련 5,000 — 거래를 암시하는
  대사 변화(상점은 훅), 85,000 — "결계"를 언급하며 다음 확장(심층 구역)을 예고.
  달인풍 비정형 숫자 문턱 1개(예: 63,235)를 눈의마을 주민에게 심는다 — 넘으면
  자랑이 감탄으로 바뀐다. 전부 **먼저 예고하지 않는 대사**다.
- 수집가의방(4종 각 5,000)·결계 통로(조건부 전환)·광산의방(확정 파밍)은 명시적
  훅 — 조건부 전환은 새 시스템이라 별도 아크.

## 7-앞. 깨끗한 세션 평가 반영 (규범 — 위 절과 충돌하면 이 절이 이긴다)

**산수·명칭 정정**

1. 신규 채집 재료는 14종이 아니라 **17종**(얼음3+나무4+허브5+광물5), 채집물 총
   **25종**. §8-6 의 아이콘 기준도 25종. 신규 아이콘 선정은 ~16종(예비
   ore_mithril·ingot_mithril 재사용, mithril_pickaxe 는 pickaxe_reinforced 재사용
   여부를 대조 시트에서 결정 — 이름이 어긋나면 새로 고른다).
2. 은퇴 함수의 실명은 `calcGatherChance`(gather.ts)다. 함께 은퇴:
   `yieldBonus`·`MAX_YIELD_BONUS`·`YIELD_DECADES`(proficiency.ts — 살려두면
   고숙련 잭팟이 3개씩 나와 표의 질량 설계가 ×3 된다), `toolCoversNode`·
   `toolAppliesTo` 의 tier 게이트 역할, `selectGatherChance`(클라, 소비자 0),
   `GatherOutcomeDto.chance`. effect kind `nodes` 는 존재 이유(노드 게이트)가
   소멸하므로 타입·파서·테스트에서 은퇴.

**표의 형태와 검증 (치명 2건의 교정)**

3. **CSV 는 세 파일이다** — 한 줄=(표,브라켓,티어) 162행의 세로 단조 수열은
   사람이 못 다룬다:
   - `gather_tables.csv`: `tableId,skill,skillGainMin,skillGainMax` (4행) —
     성패 무관 숙련 증가치는 **표 메타가 소유**하고 min≤max 검증을 계승한다.
   - `gather_tiers.csv`: `tableId,tier,itemId` (25행) — 사다리 정의.
   - `gather_brackets.csv`: `tableId,bracketMax,cum1..cum7` (브라켓당 1행,
     짧은 사다리는 우측 빈 칸) — 원작 덤프의 브라켓 블록과 1:1 눈 대조가 된다.
4. **∞ 브라켓**: `bracketMax` 빈 칸 = ∞. 표마다 **정확히 하나, 마지막 위치**를
   빌드가 강제한다(없으면 고숙련에서 판정 불능 — 라이브에서 터진다).
5. 검증 추가(§3.1 목록에 더해): `nodes.tableId` 참조 무결성 / 어느 노드도 안
   가리키는 고아 표 / 한 표를 두 기술의 노드가 공유 금지 / 누적은 **순증가**
   (같은 값 = 폭 0 = 영원히 안 나오는 티어 → 오류) / cum 칸 수 = 그 표의 티어
   수 / 마지막 브라켓 실패 0% 는 **경고**로 승격(§8-3 과 한 몸) /
   `requiredSkill > 0` 인 레시피는 정확히 하나의 recipes-이정표에 실린다(역방향
   — 잊으면 목록방에서 조용히 빠진다).
6. **광물 10단→7단 대응 규칙**: 유지 티어는 원작 누적값을 그대로 쓰고, 삭제
   티어(황동·에메랄드·다이아 상당)는 **행만 지운다** — 그 질량은 표의 다음
   행(더 흔한 이웃)에 자동 흡수된다. 검증: 광물 표의 브라켓별 마지막 누적이
   원작과 동일(20000/25000/70000/80000/90000/100000). B5 에서 금의 폭이
   15%→35%로 커지는 것은 수용한다(다이아 질량의 귀속처).

**판정·아키텍처**

7. **판정 순서**: 티어 판정 → 숙련 증가(무조건) → `newlyAchieved` 재판정
   (**무조건** — 실패한 손질이 문턱을 넘겨도 축하가 침묵하면 안 된다) →
   아이템 지급(성공 시). DTO 주석("실패 경로에서는 빈 배열")도 함께 고친다.
8. **`canGather` 를 명시 조건으로 재정의**: "그 기술의 도구가 착용됨
   (`equippedToolTier > 0`)". 현행은 tier 비교의 부수효과라 순진하게 tier 만
   지우면 맨손 채집이 열린다. 맨손 거부 테스트 추가.
9. **확률표는 클라이언트에 배송하지 않는다** — 브라켓 경계·잭팟 확률이 곧 숨은
   문턱인데 GameData 에 실으면 F12 로 스포일된다. 빌드가 서버 전용 산출물
   (`gather-tables.json` 류)을 별도로 내고 **apps/server 만 import** 한다.
   클라이언트는 판정 결과만 받는다(노드 마커도 표 내용이 필요 없다).
10. **노드 시각 변형**: nodes.csv 에 `variant` 칸(표시 전용) — 마커 색의 현행
    출처(tier)를 대체한다. 기존 8개 node id 유지로 .tmx 무수정 성립(검증 완료).

    > **정정(2026-08-13, 결계 아크): "표시 전용" 은 더 이상 참이 아니다.**
    > 이 한 마디가 코드 세 곳(`NodeDef.variant` 주석·`tokens.css`·서버 테스트)에
    > 그대로 옮겨 적혔고, 그 문장이 사는 동안 심층 넷은 이름과 색뿐이었다.
    > `variant=deep` 은 이제 `tableId` 가 `*_deep` 이라는 뜻이고, 그 표는 다른
    > 분포를 굴린다 — 판정에 **간접적으로** 쓰인다. 여전히 참인 절반은
    > "노드에는 판정에 쓰이는 티어가 없다" 쪽이다(§7-앞 8 의 등급 게이트 폐지).

    원작 대비 압축이지만 **온라인 리메이크의 의도된 압축으로 수용한다** — 원작의
    상징 숫자(5,000 거래·85,000 결계·63,235 달인)를 보존하는 값이 압축보다
    크고, 표는 데이터라 체감 후 조정이 싸다.

    > **정정(2026-08-13): 셋 중 85,000 만 원작의 숙련 문턱이 아니다.**
    > 원작 덤프를 다시 읽어 확인했다 — `v11 = 랜덤`, `v42~45 = 계열별 채집숙련도`.

    > - **63,235 달인**: 진짜다. `econ_master.txt`·`map002` 가 `v42 ≥ 63235`.
    > - **85,000**: 게이트가 **아니다**. `CE 259` 의 `[111:CondBranch] 1, 11, 0, 85000, 2`
    >   는 **랜덤 ≤ 85,000**, 즉 누적 확률표의 마지막 문턱이다(그 위는 꽝) — 우리 표의
    >   "∞ 브라켓 마지막 누적"과 같은 자리이고, 숙련도와는 무관하다.
    >
    > 그런데 이 오독 위에 대사가 이미 넷 심겼다(`채집장노인`·`광산노인`·
    > `숲마을벌목꾼`·`항구약초지기` 가 전부 85,000 에서 결계를 말하고, `여관안주인`
    > 에게 소문이 있다). 그래서 **결계는 원작 복원이 아니라 우리가 한 약속이다.**
    >
    > > **정정의 정정(2026-08-13, 결계 아크 B6): `여관안주인` 에게는 소문이 없다.**
    > > 그 파일에 결계를 말하는 줄은 하나도 없고, 세 규칙 전부 자기 기록(63,235)
    > > 이야기다. 틀린 것은 `여관안주인.dlg:11` 의 **주석**이었고 이 문장은 그
    > > 주석을 사실로 옮겨 적은 것이다(결계 §9-앞 19 — 주석도 함께 고쳤다).
    > > 결계를 말하는 화자는 다섯이 아니라 **넷**이다. 남은 결론은 그대로다.
    > 지키는 것은 여전히 옳다 — 출하된 대사가 없는 것을 가리키고 있는 쪽이 더 나쁘다.

## 8. 성공 기준

1. 숙련 0 캐릭터가 얼음을 캐면 대부분 얼음 조각이지만, 수백 번에 한 번 상위
   재료가, 이론상 첫 손질에도 얼음의 보석이 나올 수 있다(시뮬레이터/테스트 증명).
2. 브라켓을 넘는 순간 산출 분포가 계단식으로 바뀐다 — 15만 전후 1,000회 시뮬
   비교로 증명.
3. 실패한 채집도 숙련을 올린다. 최종 브라켓에서 실패가 0%다.
4. 네 채집장 모두 §4 사다리 전 티어가 실제로 드랍된다(테이블 검증 + 시뮬).
5. 철 도구가 구리보다, 미스릴이 철보다 희귀 티어를 체감되게 더 뽑는다(시뮬 비교).
6. 22종 전부 전용 아이콘(3중 유일성 테스트 확장), 새 레시피 3종이 제작 패널에서
   잠긴 문으로 보인다.
7. `pnpm data:build` 가 표의 모든 오류(누적 역전, 브라켓 중복, 없는 아이템)를
   작가용 메시지로 막는다.
8. 기존 세이브 호환: 기존 8종 id 불변, 인벤토리·착용 그대로.
