# NPC 일과 설계 — 시간의 순수 함수

**날짜:** 2026-08-10 (깨끗한 세션 평가 12건 반영)
**상태:** 설계 확정, 계획 작성 전
**전제:** 다중 맵(`transitions.csv`), 월드 시계(`time.ts`, 게임 하루 = 실제 1시간),
`NpcSprite` 위치 공급자, 서버 권위 대화(`/api/talk`).

---

## 1. 목표와 원칙

NPC가 매일 반복되는 일과를 산다 — 밤에는 자고, 아침에 나와서 일하고, 쉬고,
때로 다른 곳에 다녀온다. 이벤트가 아니라 **세계의 기본 상태**로.

**중심 결정: NPC 위치는 시간의 순수 함수다.**

```
npcStateAt(schedule, bakedRoutes, nowMs)
  → { mapId, tile, facing, activity: 'standing' | 'walking' | 'indoor' }
```

`packages/shared` 에 산다. 서버와 클라이언트가 같은 함수를 부른다. 저장할
상태도, 밀어줄 트래픽도 없다. 숙련도 공식과 같은 자세다.

**보장의 정확한 범위:** 구조적으로 보장되는 것은 **판정의 일치**다 — 판정
(같은 맵인가, 깨어 있는가)은 맵·활동 단위라 시계 오차가 판정을 바꿀 경로가
없다. 화면 위치는 클라이언트 시계 동기화 오차만큼 어긋날 수 있는데
(`RESYNC_THRESHOLD_MS = 2000` — 최대 5칸), 이를 위해 **`worldNow()` 를
단조화한다**: 재동기 시 뒤로 튀지 않고 기울여 따라잡는다(slew). 그러면 NPC가
되감기는 일이 없고, 오차는 수 초에 걸쳐 흡수된다.

**따름정리 — 플레이어는 NPC 위치에 영향을 줄 수 없다.** 서버는 플레이어의
칸 단위 위치를 모르므로(전환 때만 갱신), "플레이어가 NPC를 막는다"는 규칙은
서버가 계산할 수 없고, 따라서 존재해서는 안 된다(사용자 확정).

**차단 규칙 — 서 있을 때만 몸이 있다:**

| NPC 상태 | 차단·상호작용 |
|---|---|
| `standing` | 칸을 차단하고 `byTile` 에 오른다 — 지금의 정적 화자와 동일. 서 있는 곳은 검증된 지점뿐이므로 기존 정적 불변식(노드·화자 겹침 금지)이 그대로 성립한다 |
| `walking` | **통과 장식이다.** 차단하지 않고, 말도 걸 수 없다. 대화 중 걸어가 버리는 문제가 원천적으로 없다 |
| `indoor` | 맵에 없다 |

플레이어와 겹치면 스쳐 지나간다 — 온라인 게임의 표준이며, 원작(막고 기다림)과
갈라지는 유일한 지점(사용자 확정).

## 2. 작가용 데이터

### 2.1 지점 — 맵이 소유한다 (Tiled `places` 오브젝트 레이어)

지점은 `.tmx` 안의 오브젝트다: 이름 = 지점 id, 속성 `indoor`(선택, bool),
`facing`(선택). `spawn`·`nodes` 와 같은 문법.

> **왜 CSV가 아닌가:** 시작 칸을 CSV에서 `.tmx` 로 옮긴 것과 같은 이유다 —
> 맵을 다시 그리면 지점이 눈에 보이는 곳에서 함께 움직인다. 좌표를 밖에 적으면
> 맵 수정이 지점을 벽 속에 남기고, 빌드는 "벽"이라고만 말한다.

- `indoor=1` 지점은 "그 문 칸에서 안으로 사라진다" — 실내 맵이 생기면 지점만
  옮기면 된다.
- 지점 id 는 전역 유일(맵을 넘어). 대화 사실·호감도 패널이 나중에 같은 이름을 쓴다.

### 2.2 일과 — `schedules/<화자id>.sched`

```
# 여관안주인 — 여관을 지키다 낮에 광장에 다녀온다
06:00 여관앞
09:00 눈광장
13:00 여관안
15:00 눈광장 | 여관앞
19:00 여관앞
22:00 여관안
```

- 한 줄 = `HH:MM 지점` — 그 시각에 **도착해 있다**. 출발 시각은 빌드가
  역산한다(도착 − 경로길이×`NPC_STEP_MS`).
  > 작가가 "22:00 여관안" 을 읽고 "22시엔 여관에 있다"로 이해하는 것이 맞다.
  > 출발 의미론이면 어디 있는지 알려고 다음 줄을 읽어야 한다.
- `A | B` 변주는 날짜 시드로 하나를 고른다. **시드의 날짜는 그 줄의 출발
  시점이 속한 날이다** — 자정을 걸치는 걸음이 도중에 목적지를 다시 뽑거나,
  자정에 순간이동하는 일이 없도록.
- 하루 단위 반복. 마지막 도착 지점에서 다음 날 첫 줄의 출발 시각까지 머문다.
  **되감기 구간(마지막 줄→첫 줄)도 같은 도착 규칙을 만족해야 한다** (빌드 검증).
- `.sched` 없는 화자(간판 등)는 지금처럼 `speakers.csv` 좌표에 고정.

## 3. 경로는 빌드가 굽는다

`pnpm data:build` 가 지점 사이 길을 빌드 타임 A\*로 계산해 생성물에 싣는다.
맵 사이는 플레이어와 같은 `transitions.csv` 간선. 런타임은 보간뿐.

- **A\* 의 걷기 판정은 클라이언트와 동일하다**: 벽 + 노드 배치 + 정적 화자
  칸 + `standing` 지점 칸. `MapTerrain.walls` 만 보면 안 된다.
- **개발맵은 경로 그래프에서 제외한다** (눈의마을 서문에 붙어 있지만 개발
  전용이다).
- 걷기 속도 `NPC_STEP_MS = 400` (실제 ms/칸, 플레이어의 절반).

**빌드가 막는 것:**
- 없는 지점·없는 화자·형식 오류·`25:00` 류 시각·**중복 시각**(조용히 앞줄을
  죽이므로 오류다)·시각 역행
- 지점이 벽·노드·다른 지점·**전환 칸·전환 도착 칸** 위 (서 있는 NPC가 문을
  봉쇄한다 — `validateMapSpawns` 와 같은 이유)
- 경로 부재 — **양방향 모두** (한쪽 문만 있으면 갈 수는 있는데 못 돌아온다)
- 도착 불가능한 시간표: 각 줄의 역산 출발 시각 ≥ 앞 줄의 도착 시각, 되감기
  구간 포함
- 한 줄짜리 일과의 되감기(자기 자신으로의 0길이 걸음)는 "하루 종일 그 지점" 으로
  정의한다 — 0으로 나누지 않는다

경고만: 두 NPC가 같은 시각 같은 지점(겹쳐 서기 — 의도일 수 있다).

## 4. 함수의 의미론

**시간 축은 실측 ms 다.** `minuteOfDay`(해상도 2.5초 = 6칸)를 쓰면 NPC가
껑충껑충 뛴다. 하루 시작 실측 ms 를 기준으로:

- 활성 줄 = 도착 시각이 지금보다 과거인 마지막 줄(자정 넘김 포함, 어제의
  마지막 줄이 활성일 수 있다).
- 다음 줄의 역산 출발 시각 전이면 → 활성 줄 지점에 `standing`.
- 출발~도착 사이면 → `walking`, 구운 경로 위의 칸(진행도 = 경과 실측 ms /
  `NPC_STEP_MS`), facing = 진행 방향. 경로가 맵을 넘는 구간에서 mapId 가 바뀐다.
- `indoor` 지점에 도착해 있으면 → `indoor` (맵에 없음).
- 함수는 전역(total)이다 — 빈 일과·한 줄 일과·자정 경계·재동기 직후를 포함한
  모든 입력에 답이 있고, 그 경계들이 전부 순수 함수 테스트로 못박힌다.

## 5. 서버

- 일과 있는 NPC: `npcStateAt` 로 판정 — 다른 맵이면 `wrong_map`, `indoor` 나
  `walking` 이면 새 코드 **`not_here`**.
- 일과 없는 화자: 지금처럼 정적 좌표.
- **클라이언트 표면까지가 이 스펙이다**: `not_here` 를 게임 스토어가 받아
  대사창 자리에 "지금 여기 없는 것 같다" 안내를 띄운다. (지금 실패 코드는
  콘솔에만 가고 플레이어에게 아무것도 안 보인다 — 그 구멍을 함께 막는다.)

## 6. 클라이언트

- `WorldScene` 스케줄러 틱: 현재 맵의 일과 NPC를 `npcStateAt` 로 샘플링해
  `NpcSprite` 공급자에 민다. 걷기 애니메이션은 칸 변화가 만든다.
- **스폰·프리로드는 `npcStateAt` 기준이다** — `speaker.mapId` 가 아니라
  "지금 이 맵에 있는가". 이 맵의 일과가 데려올 수 있는 모든 NPC 의 시트를
  미리 싣는다(일과가 참조하는 지점의 맵으로 판단).
- `blocked`/`byTile` 갱신은 `standing` 전이 시에만 — `walking` 은 차단하지
  않으므로 틱마다 만질 것이 없다.
- **facing 소유권**: 스케줄러는 걷는 동안의 facing 만 소유한다. `standing`
  중에는 기존 미세 동작(무작위 방향 전환, 말 걸면 돌아보기)이 소유한다 —
  틱이 지점 facing 을 매 프레임 덮어쓰면 그 둘이 한 프레임 만에 지워진다.
- `worldNow()` 단조화(slew)는 `clock.ts` 에서 한 번 — 모든 소비자가 혜택.

## 7. 무엇을 안 하는가 (훅만)

- 호감도 위치 패널 / `npc.activity`·`npc.place` 대화 사실 / 실내 맵 /
  날씨 예외 / NPC 끼리 회피(겹침 허용이라 불필요) / **시뮬레이터 `content npc`
  명령**(도구 확장은 별도 작업 — 이번엔 순수 함수 테스트가 그 역할을 한다).

## 8. 첫 콘텐츠 (검증 겸)

- **여관안주인** (§2.2 예시): 유일한 첫 통근자. 지점은 전부 눈의마을 안 —
  맵 하나 안에서 시스템 전체(걷기·indoor·변주·not_here)가 검증된다.
- **채집장노인**: **맵 안 순찰만** — 06:00 초소, 12:00 심층 광맥 곁, 15:00
  초소. 밤에도 채집장에 남는다(indoor 없음, 언제나 대화 가능).
  > 왜 통근이 아닌가: 노인은 시작 채집장의 유일한 화자이고 `ice_10000`
  > 문턱 대사의 주인이다 — 밤마다 사라지면 핵심 루프의 반응성 1/3이 죽는다.
  > 맵 사이 통근 시연은 실내 맵이 생길 때 다른 NPC로 한다.
- 나머지 주민은 이번엔 고정.

## 9. 성공 기준

1. 서버를 껐다 켜도, 새로고침해도 NPC는 항상 "그 시각의 제자리"에 있다.
2. 눈의마을에서 여관안주인이 시각에 맞춰 문 앞↔광장을 걸어 다니는 것을 볼
   수 있고, 걷는 동안에는 몸이 없어 말 걸 수 없고 지나칠 수 있다.
3. 밤(실내)에 말을 걸면 대사창 자리에 "지금 여기 없다" — 낮에는 평소처럼.
4. `standing` NPC 칸은 못 들어가고, 내가 길을 막아도 NPC는 겹쳐 지나간다.
5. 일과 경로를 끊는 맵 수정, 불가능한 시간표, 문을 막는 지점은
   `pnpm data:build` 가 즉시 막는다.
6. `npcStateAt` 경계(자정 넘김, 출발 직전/직후, 도착 순간, 변주 시드의 날짜
   귀속, 한 줄 일과, 재동기 slew)가 전부 순수 함수 테스트로 못박힌다.
