# NPC 일과 설계 — 시간의 순수 함수

**날짜:** 2026-08-10
**상태:** 설계 승인됨(사용자), 깨끗한 세션 평가 전
**전제:** 다중 맵(`transitions.csv`), 월드 시계(`time.ts`, 게임 하루 = 실제 1시간),
`NpcSprite` 의 위치 공급자 인터페이스, 서버 권위 대화(`/api/talk`).

---

## 1. 목표와 원칙

NPC가 매일 반복되는 일과를 산다 — 밤에는 자고, 아침에 나와서 일하고, 쉬고,
때로 다른 곳에 다녀온다. 이벤트가 아니라 **세계의 기본 상태**로.

**중심 결정: NPC 위치는 시간의 순수 함수다.**

```
npcStateAt(schedule, bakedRoutes, nowMs)
  → { mapId, tile, facing, activity: 'standing' | 'walking' | 'indoor' }
```

`packages/shared` 에 산다. 서버와 클라이언트가 **같은 함수를 부르므로 위치
차이가 구조적으로 존재할 수 없다** — 동기화가 아니라 같은 계산이다. 저장할
상태도, 밀어줄 트래픽도 없다. 숙련도 공식과 같은 자세다.

**따름정리 — 플레이어는 NPC 위치에 영향을 줄 수 없다.** 서버는 플레이어의
칸 단위 위치를 모르므로(전환 때만 갱신), "플레이어가 NPC를 막는다"는 규칙은
서버가 계산할 수 없고, 따라서 존재해서는 안 된다(사용자 확정). 충돌은 비대칭:

| | 규칙 |
|---|---|
| 플레이어 → NPC | 막힘. NPC가 선 칸은 못 들어간다(노드와 동일). 앞칸 대화 판정 유지 |
| NPC → 플레이어 | 통과. 겹치면 스쳐 지나간다 — 온라인 게임의 표준이고, 원작과 갈라지는 유일한 지점(사용자 확정) |

남는 오차는 시계 동기화 오차(수십 ms)뿐이며, 판정(같은 맵인가·깨어 있는가)은
맵·시간 단위라 그 오차가 판정을 바꿀 경로가 없다.

## 2. 작가용 데이터

### 2.1 지점 등록부 — `csv/places.csv`

```csv
id,mapId,x,y,indoor,facing
눈광장,눈의마을,10,19,0,down
여관앞,눈의마을,9,14,0,down
여관안,눈의마을,9,14,1,down
채집장초소,얼음채집장,16,22,0,down
```

- `indoor=1` 은 "그 문 칸에서 안으로 사라진다" — 실내 맵이 아직 없으므로
  despawn 으로 표현한다. 실내가 생기면 지점의 mapId 만 바꾸면 된다.
- `facing` 은 도착 후 서서 바라보는 방향(기본 down).
- 지점은 NPC 사이에 공유된다 — 대화 사실·호감도 패널이 나중에 같은 이름을 쓴다.

### 2.2 일과 — `schedules/<화자id>.sched`

```
# 여관안주인 — 여관을 지키다 낮에 광장에 다녀온다
06:00 여관앞
09:00 눈광장
13:00 여관안
15:00 눈광장 | 여관앞 | 채집장초소
19:00 여관앞
22:00 여관안
```

- 한 줄 = `HH:MM 지점` — 그 시각에 **출발**한다. 도착은 걸음 속도와 경로
  길이가 정한다.
- `A | B | C` 는 날짜 시드로 하나를 고른다 — `seed(화자id, 날짜, 줄번호)`.
  매일 다르지만 서버·클라이언트·시뮬레이터 모두 같은 답이다.
- 하루 단위로 반복. 마지막 줄과 첫 줄 사이는 마지막 지점에 머문다(자정 걸침).
- `.sched` 가 없는 화자(간판, 아직 일과를 안 쓴 NPC)는 지금처럼
  `speakers.csv` 의 x·y·facing 에 고정된다.

## 3. 경로는 빌드가 굽는다

`pnpm data:build` 가 지점 사이 걷는 길을 **빌드 타임에 A\*** 로 계산해
생성물에 싣는다. 맵 사이는 플레이어와 같은 `transitions.csv` 간선을 쓴다 —
NPC도 같은 문으로 다닌다(사용자 요구). 런타임은 보간뿐: 서버 CPU 0,
경로 탐색 0.

걷기 속도: `NPC_STEP_MS = 400` (실제 ms/칸, 플레이어 200의 절반). 게임
시간으로 칸당 0.16분 — 월드맵 횡단(~150칸)이 약 24게임분, 그럴듯하다.

**빌드가 막는 것** (작가의 실수는 빌드가 찾는다):
- 없는 지점·없는 화자를 가리키는 일과
- 지점이 벽·노드 위이거나 맵 밖
- **경로가 존재하지 않는다** (맵을 고쳐 길이 끊기면 그 자리에서 실패)
- **한 구간이 다음 출발 시각 전에 도착할 수 없다** — 중간 경로 변경은 순수
  함수를 깨므로, 시간표가 물리적으로 가능함을 빌드가 보증한다
- 시각 역행, 형식 오류

경고만: 두 NPC가 같은 시각 같은 칸(겹쳐 서기 — 의도일 수 있다).

## 4. 함수의 의미론

하루를 게임분(0..1439)으로 접는다. 활성 줄 = 시각 ≤ 지금 인 마지막 줄.

- 출발 시각 + 경로길이×`NPC_STEP_MS` 이전이면 → `walking`, 구운 경로 위의
  칸(진행도 = 경과/`NPC_STEP_MS`), facing = 진행 방향. 맵 경계를 넘는 순간
  mapId 가 바뀐다 — 클라이언트에서는 전환 칸에서 사라지고 도착 칸에서
  나타나는 것으로 보인다.
- 도착 후면 → 지점에 `standing`, 지점의 facing. `indoor=1` 이면 `indoor`
  (맵에 없음).
- 함수는 전역(total)이다 — 어떤 시각을 넣어도 답이 있다. 시뮬레이터가 이를
  그대로 쓴다: `pnpm content npc 여관안주인 --hour=14` 가 어디 있는지 답한다
  (도구 확장은 범위 밖, 훅만).

## 5. 서버

`talkService` 의 화자 위치 검사가 바뀐다:

- 일과 있는 NPC: `npcStateAt(...)` 로 현재 맵을 계산해 `wrong_map` 판정.
  `indoor` 면 새 코드 **`not_here`** 로 거절 — 클라이언트는 "지금 여기 없다"
  로 보여준다.
- 일과 없는 화자: 지금처럼 `speakers.csv` 고정 좌표.

이게 서버 변경의 전부다. 무작위성 없음(시드 결정적), 상태 없음.

## 6. 클라이언트

- `WorldScene` 에 스케줄러 틱: 현재 맵의 일과 NPC들에 대해 `npcStateAt` 를
  샘플링해 `NpcSprite` 위치 공급자에 밀어 넣는다. 걷기 애니메이션은 칸 변화가
  만든다(플레이어와 같은 워크 프레임).
- 맵에 들어올 때: 지금 이 맵에 있는 NPC만 스폰. 일과가 NPC를 맵 밖으로
  데려가면 despawn, 들어오면 spawn — 전부 같은 함수의 답.
- `blocked`/`byTile` 는 NPC의 **현재 계산 칸**을 따라 움직인다(진입 차단과
  앞칸 대화가 살아 있도록). 갱신은 칸이 바뀔 때만.
- 기존 미세 동작(무작위 방향 전환, 말 걸면 돌아보기)은 `standing` 중에만.

## 7. 무엇을 안 하는가 (훅만 남긴다)

- **호감도 위치 패널** — 같은 함수가 "지금 어디"를 답하므로 나중에 UI만.
- **활동별 대사** — `npc.activity`/`npc.place` 사실 공급은 사실 프레임워크에
  몇 줄이지만, 대사 작성과 함께 별도 작업으로.
- **실내 맵** — `indoor` despawn 으로 대신. 실내가 생기면 지점 갱신만.
- **NPC 끼리 회피, 군중** — 겹침 허용이므로 불필요.
- **일과 중 예외(비 오면 집에)** — 날씨 스펙과 함께.

## 8. 첫 콘텐츠 (검증 겸)

- **여관안주인**: 위 예시 일과 — 아침 문 앞, 광장 나들이, 점심 실내, 오후
  변주(셋 중 하나), 저녁 문 앞, 밤 실내.
- **채집장노인**: 06:00 눈의마을 집앞 → 채집장초소로 **출근**(맵 전환 포함
  — 시스템 전체의 시연), 22:00 퇴근 후 실내. 낮에는 지금처럼 채집장에.
- 나머지 주민은 일과 없이 고정(다음 콘텐츠 작업에서 추가).

## 9. 성공 기준

1. 서버를 껐다 켜도, 새로고침해도 NPC는 항상 "그 시각의 제자리"에 있다.
2. 아침 6시(게임) 직후 눈의마을에서 노인이 집을 나서 북문으로 걸어가는 것을
   볼 수 있고, 따라가면 채집장 초소에 도착해 선다.
3. 밤에 여관안주인에게 말을 걸면 `not_here` — 낮에는 평소처럼 대화.
4. 걷는 NPC의 칸에 들어갈 수 없고, 내가 길을 막아도 NPC는 겹쳐 지나간다.
5. 일과 경로를 끊는 맵 수정은 `pnpm data:build` 가 즉시 막는다.
6. 테스트: `npcStateAt` 의 경계(자정, 출발 직전/직후, 도착 순간, 변주 시드,
   indoor)가 전부 순수 함수 테스트로 못박힌다.
