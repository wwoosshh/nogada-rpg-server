# 다중 맵과 맵 전환 설계

**날짜:** 2026-08-09
**상태:** 설계 승인됨, 계획 작성 전
**다음 스펙:** 맵 저작 도구 → 세계 구축 → NPC 일과

---

## 1. 왜 이것이 먼저인가

엔진이 맵 하나에 못박혀 있다.

- `apps/client/.../WorldScene.ts:2` 가 `world.json` 을 **정적 import** 한다
- `packages/data/src/build.ts:54` 도 `maps/world.json` 하나만 읽는다
- `speakers.csv` 의 `mapId` 는 파싱만 되고 **아무도 안 읽는다**
- `validateSpeakerPlacements` 는 지형 하나만 받는다
- `PlayerState` 에 위치가 **아예 없다** — `mapId` 도 `x`·`y` 도. 새로고침하면 항상 첫 스폰

맵을 아무리 많이 만들어도 게임이 못 연다. 그리고 그 다음 작업들 — 맵 저작 도구,
세계 구축, NPC 일과 — 이 전부 이것 위에 올라간다. NPC 가 맵 사이를 오가려면 맵
사이를 오가는 길이 먼저 있어야 한다.

**처음 순서는 저작 도구가 먼저였다.** 독립 평가가 뒤집었고 그 논거가 옳았다:
게임이 못 여는 맵을 서른 개 만들어 봐야 값어치가 없고, 저작 도구의 형식이 지금
추측하고 있는 것들(지형 종류가 몇인가, 밀도가 얼마인가)은 **맵을 몇 장 그려 보면
알게 되는 것들**이다. 그래서 이 스펙은 손으로 그린 맵 서너 장으로 끝나고, 그
서너 장이 다음 스펙의 요구사항이 된다.

## 2. 원작에서 확인한 것

원작(RPG Maker XP, 맵 430개 중 410개 도달 가능)을 디코드해서 얻었다.

- **전환의 70%가 맵 가장자리의 "플레이어 접촉" 이벤트다.** 문을 찾아 누르는 게
  아니라 맵 끝으로 걸어 나가면 넘어간다.
- **맵 하나에 문이 둘.** 전환 타일 수의 중앙값 3, 목적지 수의 중앙값 2.
- **하나로 이어진 덩어리.** 417개 맵이 한 컴포넌트를 이루고, 방향쌍의 82%가 양방향이다.
  걸어서 세계 끝까지 갈 수 있다.
- 그 위에 공통 이벤트 점프 1,426건이 얹혀 있는데 1,078건이 **사망 후 병원 복귀**다.
  상점·창고 같은 모달 방은 부른 쪽 좌표를 변수에 저장했다가 되돌려 보낸다.

이 스펙은 **가장자리 접촉 전환**만 만든다. 사망 복귀와 모달 방은 각각 그 기능이
생길 때 만든다.

## 3. 구조

### 3.1 맵 등록부

```
# csv/maps.csv
id,name,file
world,얼음 채집장,world.json
숲길,숲 길,forest-path.json
```

정적 import 가 사라지고 클라이언트는 **필요한 맵만 실행 중에 받아 온다**. 맵이
수십 개가 되어도 첫 로딩이 무거워지지 않는다.

### 3.2 `.tmx` → `.json` 을 빌드가 한다

지금은 Tiled 에서 "Export As" 를 손으로 눌러야 `.json` 이 나온다. 맵이 하나일 땐
견딜 만하지만 서너 장만 되어도 빠뜨린다 — 그리고 빠뜨리면 **저장했는데 게임은
옛 맵**이라는, 원인을 짚기 어려운 실패가 된다.

빌드가 `maps/*.tmx` 를 읽어 `.json` 을 만든다. 사장님은 Tiled 에서 저장만 하면 된다.

이건 다음 스펙(저작 도구)이 그대로 다시 쓴다 — 생성기도 결국 `.json` 을 내놓아야
게임에 닿기 때문이다.

### 3.3 타일셋 경로를 고친다

`world.json` 은 타일셋을 `../tilesets/pipoya-basechip.png` 로 가리키는데 **그 폴더가
없다.** 실제 이미지는 gitignore 된 `apps/client/public/tilesets/` 에만 있다. 지금은
게임이 `.json` 에 박힌 타일 번호로 돌아가서 티가 안 나지만, **Tiled 에서 열면
타일셋이 깨진 채로 열린다.**

맵을 손으로 그리는 것이 이 스펙의 산출물이므로 여기서 고친다. 라이선스상 이미지는
저장소에 못 올리니, 경로를 실재하는 위치로 맞추고 복원 방법을 `assets/CREDITS.md`
가 이미 하듯 적어 둔다.

### 3.4 서버가 위치를 갖는다

```ts
// PlayerState 에 추가
location: { mapId: string; x: number; y: number }
```

**왜 서버인가:** 어느 맵에 있는지는 판정에 쓰인다. 지금 `/api/talk` 은 맵 너머의
화자에게도 말을 걸 수 있고(대화 스펙의 남은 구멍), `/api/gather` 도 마찬가지다.
서버가 `mapId` 를 알면 **"그 노드는 네가 있는 맵에 없다"** 를 거절할 수 있다.

칸 단위 위치까지 서버가 갖되, **걸음마다 보내지는 않는다.** 전환할 때 갱신하고,
그때 도착 칸을 서버가 정한다. 매 걸음을 서버에 보내는 것은 이 게임에 필요 없고
(전투도 PvP 도 없다) 노가다 루프에 왕복 지연을 얹는다.

기존 세이브에는 이 필드가 없으므로 `dialogueHistory` 와 같은 이유로 **기본값**을
둔다 — 없으면 시작 맵의 스폰 지점.

### 3.5 전환

```
# csv/transitions.csv
fromMap,fromX,fromY,toMap,toX,toY,facing
world,15,0,숲길,15,28,up
world,15,29,항구길,15,1,down
```

그 칸을 **밟으면** 넘어간다(원작의 70%가 이 방식). 누르는 문은 이 스펙에 없다 —
필요해지면 `kind` 열을 더한다.

`facing` 은 도착 후 바라보는 방향이다. 없으면 들어온 방향을 그대로 유지한다.

**왜 CSV 이고 맵 오브젝트가 아닌가:** 전환은 맵 *두 개*에 걸친 사실이다. 한쪽
맵 파일에 넣으면 반대쪽과 어긋나도 알 수 없다. CSV 한 곳에 모으면 빌드가 양쪽을
같이 본다(4절).

### 3.6 배치는 지금 자리에 둔다

채집 노드는 계속 각 맵 `.tmx` 의 `nodes` 오브젝트 레이어에 있고, 화자는 계속
`speakers.csv` 에 있다. 갈라져 있지만 **의도적으로 둔다:**

- 노드는 **빽빽하고 공간적이다**(원작은 맵당 약 21개). Tiled 에서 찍는 게 훨씬 빠르다.
- 화자는 **드물고 데이터가 많다** — 이름, 종류, 대사 파일과 이어진다. CSV 가 맞다.

다음 스펙에서 맵을 생성하기 시작하면 `.tmx` 안의 오브젝트가 재생성 때 위험해진다.
그때 옮길지 말지를 정한다 — 지금 정하면 근거 없이 정하는 것이다.

바뀌는 것은 **양쪽 다 맵별로 읽힌다**는 것뿐이다.

### 3.7 클라이언트

전환은 `WorldScene` 을 **다시 시작**한다 — 부분 갱신보다 단순하고, 지금 씬이
`create()` 에서 세우는 것(타일 레이어, 노드 표지, 화자, 충돌 집합)이 전부 맵에
매인 것들이라 어차피 전부 다시 세워야 한다.

전환 순간에는 **입력을 잠근다.** 대화·패널과 같은 주인 있는 잠금(`lockedBy`)을
쓴다 — 이미 그 구조가 있다.

## 4. 검증

빌드가 막는 것:

- `maps.csv` 가 없는 파일을 가리킨다
- 전환의 출발·도착 맵이 등록부에 없다
- 전환의 출발 칸이나 도착 칸이 **맵 밖**이다
- **도착 칸이 벽이거나 노드 위다** — 도착하자마자 낀다
- 두 전환이 같은 출발 칸을 쓴다
- 배치·화자의 `mapId` 가 등록부에 없다 (지금은 아무도 안 읽어서 오타가 통과한다)
- **시작 맵에서 걸어서 못 닿는 맵이 있다** — 이정표 검증이 이미 하는 도달 가능성 검사와 같은 자세

경고만 하는 것:

- 전환이 한쪽 방향만 있다 — 일방통행은 의도일 수 있다(원작도 18%가 그렇다)
- 맵에 전환이 하나도 없다

## 5. 산출물

**손으로 그린 맵 서너 장.** 지금 맵(`world`) 에 더해 최소 두 장, 서로 다른 지형으로.
이것이 이 스펙이 돌아간다는 증거이자 **다음 스펙의 요구사항**이다 — 저작 도구는
이 맵들을 재현하는 것을 목표로 만든다.

원작의 밀도를 참고한다: 화면 1~3개 크기, 입구 하나 출구 하나, 바닥 60칸당 노드
하나 정도(지금 맵은 30×30 에 13개로 헐렁하다).

## 6. 성공 기준

1. 맵 가장자리로 걸어 나가면 다음 맵으로 넘어가고, 되돌아오면 나온 자리로 돌아온다.
2. **새로고침해도 있던 맵, 있던 자리에 있다.**
3. 다른 맵의 노드를 캐거나 화자에게 말을 거는 요청을 서버가 거절한다.
4. 전환 도착 칸을 벽 위로 옮기면 빌드가 막는다.
5. Tiled 에서 맵을 저장하고 `pnpm data:build` 만 하면 게임에 반영된다 — Export As 없이.
6. Tiled 에서 맵을 열면 타일셋이 제대로 보인다.

## 7. 무엇을 안 하는가

- **맵 저작 도구** — 다음 스펙
- **누르는 문, 사망 복귀, 모달 방** — 그 기능이 생길 때
- **걸음마다 서버 동기화** — 3.4 참고
- **NPC 가 맵을 넘나드는 것** — 일과 스펙. 다만 전환 지점을 NPC 도 쓸 수 있도록
  데이터를 맵 밖에 둔다(3.5)
