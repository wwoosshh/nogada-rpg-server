# 도구 루프 개편 설계 — 첫 도구를 만드는 날 세상이 달라진다

**날짜:** 2026-08-12
**상태:** 설계 초안, 깨끗한 세션 평가 전
**사용자 요구(원문 요지):** 장비가 제구실을 못한다. 만든 장비를 또 만들 수 있고,
"채집→재료→도구 제작→그 도구로 더 빠르고 효율적인 채집" 루틴이 작동하지 않는다.
장비를 입거나 교체하는 것도 불가능하다. 유저가 플레이할 동기를 심는 구조로 개편하라.

**진단(현행 코드 확인):**
- 채집 도구는 품질(roll ×0.9/0.8 + 잭팟 평감산)만 올린다 — **속도 축이 없다**.
  원작은 도구가 대기시간을 줄였다(Wait 8→6→4, ce/260 확인).
- `STARTING_TOOL_IDS` 가 구리 4종을 전부 지급 — 첫 도구 제작의 순간이 없고,
  구리 도구 레시피 자체가 없다(철·미스릴만 제작 가능).
- 수동 착용 API 없음(자동 착용뿐). 가방 슬롯은 보기 전용.
- 중복 제작품(예비 도구)은 용도 0. `ItemInstance.enhanceLevel` 은 "구조는
  처음부터 분리해 둔다"는 주석과 함께 항상 0.
- 망치는 이미 제작 성공률 보조로 작동(`calcCraftSuccess` 의 tier 보너스) — 유지.

---

## 1. 목표

시작 마을의 도구 하나로 시작해, 맨손으로 힘겹게 다른 재료를 모으고, 첫 도구를
만드는 순간 채집이 눈에 띄게 빨라진다. 같은 도구를 또 만들면 그것은 낭비가
아니라 강화 재료다. 도구는 언제든 손으로 바꿔 낄 수 있다.

## 2. 결정 1 — 도구 게이트 폐지 (원작 복귀), 시작 지급 축소

- **맨손 채집 허용.** `canGather` 의 도구 요구(G3 에서 명시화한 그것)를 다시
  없앤다 — 원작에는 게이트가 없었고, 우리 게이트는 시작 지급 4종에 가려 한 번도
  체감된 적이 없다. 게이트 대신 **맨손 페널티**가 도구의 존재 이유가 된다(§3).
- **시작 지급 = 시작 마을 기술의 구리 도구 1개.** 눈의마을→구리 정,
  숲의마을→구리 도끼, 북동쪽마을→구리 곡괭이, 항구마을→구리 낫.
  (`villageField` 가 마을→기술을 이미 안다 — 그 대응을 재사용.)
- **구리 도구 레시피 4종 신설** (제작 카테고리 `도구`, requiredSkill 0 —
  부트스트랩 검증은 스킬당 0-레시피 "하나 이상"이라 복수 허용 확인):

| 레시피 | baseChance | skillGain | 입력 |
|---|---|---|---|
| copper_chisel | 0.55 | 12~20 | copper_ingot×1 + soft_log×2 |
| copper_axe | 0.55 | 12~20 | copper_ingot×1 + soft_log×2 |
| copper_pickaxe | 0.55 | 12~20 | copper_ingot×1 + soft_log×2 |
| copper_sickle | 0.55 | 12~20 | copper_ingot×1 + soft_log×2 |

  부트스트랩 경로(어느 마을이든 성립): 맨손으로 구리 원석·무른 통나무를 느리게
  모은다 → 구리 주괴(requiredSkill 0) → 첫 도구. 자기 마을 도구는 이미 손에
  있으므로 "내 필드는 빠르고 남의 필드는 느린" 비대칭이 첫날의 이야기가 된다.
- 기존 세이브는 무이행 — 구리 4종을 이미 가진 캐릭터는 그대로(신규 생성만 축소).

## 3. 결정 2 — 도구 효과 3축 (속도가 생긴다)

| 손 | 간격 배수(채집) | roll 배수 | 잭팟 평감산 |
|---|---|---|---|
| 맨손 | ×1.5 | ×1.1 | 0 |
| 구리(1티어) | ×1.0 | ×1.0 | 0 |
| 철(2티어) | ×0.85 | ×0.9 | −2 |
| 미스릴(3티어) | ×0.7 | ×0.8 | −3 |

- **간격 배수**: `nextActionAt` 계산에서 채집 행동에만 적용(제작은 불변).
  숙련 기반 단축(500→50ms)과 곱으로 결합.
- **roll ×1.1(맨손)**: 곱이 1보다 크면 상위 티어가 멀어지고, 표 끝(100000)을
  넘긴 몫은 실패가 된다 — 최종 브라켓에서도 맨손은 실패가 남는다(도구의 영원한
  존재 이유). 잭팟 밴드(rawRoll≤10)는 배타 적용 규칙(채집 스펙 §7-앞 13) 그대로
  — 맨손 평감산 0 이므로 맨손도 잭팟은 원확률로 가능(원작 정신).
- 망치(조합)는 현행 유지 — 성공률 보조. 간격 배수는 채집 도구만.

## 4. 결정 3 — 수동 착용

- `POST /api/equip { instanceId }` — 그 인스턴스의 `toolSkill` 슬롯에 착용
  (교체). 검증: 소유 인스턴스, kind=tool. 해제는 없다 — 맨손이 전략인 경우가
  없고, 빈 슬롯은 신규 캐릭터의 상태로 충분하다.
- 가방: 예비 도구 칩 탭 → 착용(1탭, 가역이라 확인창 없음). 착용 중 도구를
  탭하면 아무 일 없음. 장비 슬롯 UI 는 기존 것 유지(착용 결과가 슬롯에 반영).
- 자동 착용(더 좋은 도구 제작 시)은 유지 — 수동은 되돌리기·강화 대상 지정용.

## 5. 결정 4 — 중복 제작 = 강화 재료 (합성 v1)

- `POST /api/enhance { materialInstanceId }` — 재료 인스턴스(예비 도구)를
  소모해 **같은 itemId 의 착용 중 인스턴스**를 +1. 서버 검증: 재료는 미착용,
  대상은 착용 중, itemId 동일, 대상 enhanceLevel < 5(상한).
- 성공 100%(v1 — 원작식 도박 강화·각성구슬은 훅). 재료의 enhanceLevel 은
  버려진다(+2 재료도 +1 만큼만 — 단순함이 우선, 합성식은 훅).
- **효과: +1당 채집 간격 추가 ×0.97** (곱, +5 = ×0.86). 속도 하나에 집중 —
  체감이 가장 즉각적인 축이고, 효과 축을 하나로 두어야 강화의 가치가 읽힌다.
  망치 강화는 +1당 성공률 +0.5%p(같은 API, 효과만 조합 축).
- 가방 예비 도구 칩: `[착용]` `[강화]` 두 동작(강화 버튼은 같은 itemId 를 착용
  중일 때만 활성). UI 는 기존 칩 확장.
- 제작 패널: 도구 레시피 재제작 허용 유지(중복이 이제 재료다). 카드의 `보유 N`
  이 인스턴스를 세는 것(기존 수정)이 그대로 강화 재고 표시가 된다.

## 6. 무엇을 안 하는가 (훅만)

강화 실패·소멸(도박), 각성구슬류 강화 재료 아이템, 강화 시 품질(roll) 축 보너스,
도구 내구도, 해제(빈 슬롯 만들기), 장비 판매/분해, 방어구·장신구, 제작 간격 도구
보너스, 합성식(재료 레벨 승계).

## 7. 성공 기준

1. 새 캐릭터가 자기 마을 도구 1개로 시작하고, 나머지 슬롯 3칸이 빈 칸(점선)으로
   보인다.
2. 맨손 채집이 가능하되 같은 필드에서 도구 대비 느리고(간격 ×1.5) 실패가 잦다
   (시뮬로 증명 — 맨손 vs 구리 분포·간격).
3. 구리 도구 레시피 4종이 제작 목록에 열려 있고, 만들면 자동 착용되며 즉시
   간격이 짧아진다(브라우저 실측).
4. 예비 도구 칩에서 [착용] 으로 교체가 되고, [강화] 로 예비를 소모해 착용
   도구가 +1 이 되며 가방 슬롯에 +N 이 보인다. +1 후 채집 간격이 실제로 짧아진다.
5. 강화 상한(+5)·비착용 대상·다른 itemId 재료가 서버에서 거부된다(테스트).
6. 기존 세이브(구리 4종 보유)가 그대로 동작 — 이행 없음.
7. `pnpm data:build && pnpm test && pnpm typecheck` 초록, 판정은 전부 서버.
