# 가방·제작 UI 설계 — 손에 잡히는 인벤토리

**날짜:** 2026-08-11
**상태:** 깨끗한 세션 평가 3렌즈(아키텍처·UX/장르·데이터 파이프라인) 반영 완료 — §8-앞이 규범
**사용자 요구(원문 요지):** 미구현 가방을 제대로 구현하라. 제작 패널은 분류를 제대로 해서
보기 좋게 하라. 아이콘을 적극 사용하라. 상단 헤더의 "다음 이정표" 티커는 필요 없다 —
현재 서 있는 맵의 이름을 보여줘라. 원작 콘텐츠를 확장하는 개념으로.

**전제(조사로 확인된 사실):**
- 가방·제작 패널은 React 가 아니라 Phaser 캔버스다(`PanelScene.ts`). 가방은
  "아직 만들지 않았습니다" 스텁, 제작은 `craftPanelContent.ts`가 만드는 순수 텍스트
  2~3줄 × 6레시피를 `ScrollList`에 쌓은 것 — 아이콘도 카드 경계도 열 구조도 없다.
- `items.csv`에 `icon` 칼럼이 이미 있고 `ItemIcon.tsx`(현재 참조 0건인 죽은 코드)가
  `icons/{icon}.png`로 읽는다. 그러나 실물 PNG는 13장뿐이라 18개 아이템 중 6개가
  남의 아이콘을 빌려 쓴다(얼음 조각↔흔한 약초가 같은 그림, 구리 도구 4종이 같은 그림).
- `assets/licensed/icons_8.13.20/fullcolor/individual_32x32/`에 **Time Fantasy Icons
  1023장**이 라이선스 확인·CREDITS 등재 완료 상태로 대기 중이다(상업 ✅, 재배포 ❌ —
  gitignore + CREDITS 복원 레시피 관례 그대로).
- 잠긴 레시피를 요구치 숫자와 함께 보여주는 원작 장치("요구치를 숫자로 말하는 문")는
  이미 구현돼 있다 — 이 재설계에서 반드시 보존한다.
- 원작(RPG Maker XP 추출본)의 `Graphics/Icons` 258장은 **픽셀을 가져오지 않는다**
  (RTP/저작권 확인 불가). 아이템 이름 대조용 참고자료로만 쓴다.

---

## 1. 목표

컨트롤러의 가방 버튼을 누르면 내 물건이 **그림으로** 보인다 — 어떤 도구를 차고
있는지, 재료가 몇 개인지. 제작 버튼을 누르면 레시피가 분류된 카드로 보이고,
잠긴 것은 잠긴 대로 요구치 숫자를 말한다. 상단에는 지금 서 있는 곳의 이름이 있다.

## 2. 결정 1 — 가방·제작 패널을 DOM(React)으로 옮긴다

`menu`(설정·상세 탭)는 이번엔 Phaser에 남긴다. `bag`·`craft`만 이전한다.

> **왜 DOM인가:**
> 1. 이 작업의 본질이 레이아웃이다 — 아이콘+이름+수량의 가로 배치, 카드, 그리드,
>    섹션 헤더. `ScrollList`는 세로 텍스트 스택만 지원해서 Phaser에 남으면 이 전부를
>    캔버스 좌표 계산으로 새로 지어야 한다. CSS 그리드는 이걸 공짜로 준다.
> 2. 16px 격자 폰트 제약(`gameText.ts`)이 사라진다 — 수량·요구치 같은 작은 글씨를
>    흐림 없이 쓸 수 있다.
> 3. 색·폰트 이중 관리(`tokens.css` ↔ Phaser 리터럴 hex)가 이 두 패널에서는 사라진다.
> 4. 전례가 있다 — `DeleteCharacterDialog`가 같은 이유(IME)로 DOM으로 빠졌고,
>    상단바도 DOM 오버레이다. "Phaser 위에 DOM"은 이미 이 프로젝트의 검증된 패턴이다.

**배선 (스토어가 다리다):**
- `gameStore`에 `openPanel: 'bag' | 'craft' | null` + `setOpenPanel` 추가.
  DOM 패널은 이것을 구독해 렌더하고, Phaser 쪽(컨트롤러 가방/제작 버튼,
  키보드 I/C → `InputHub`)은 이 액션을 호출하는 것으로 끝난다.
- `PanelScene`에서 `bag`·`craft`를 제거한다(`menu`만 남는다). 컨트롤러
  숨김(`setControllerVisible`)은 지금과 동일하게 — 패널이 열려 있는 동안 컨트롤러가
  사라지고, 이동 입력이 막힌다(현행 `applyInput` 게이트와 동등한 규칙을 스토어
  구독으로 유지).
- 패널 DOM은 기존 `.modal` 관례를 확장한 전면 패널: 반투명 스크림 + 카드,
  `tokens.css` 변수만, Neo둥근모, `image-rendering: pixelated` 아이콘.
- 세로 375px 예산: 상단바(~34px)를 뺀 나머지를 패널이 쓰고 내부 스크롤
  (`overflow-y:auto`) — `.screen__panel`이 이미 같은 수법을 쓴다.

**보존해야 하는 상호작용 계약:**
- **누르고 있으면 반복 제작** — 현행 `ScrollList.heldGroup()` + 프레임 폴링을
  DOM 포인터 이벤트로 재현한다: `pointerdown` → 즉시 1회 + 반복 타이머,
  `pointerup`/`pointercancel`/이동 10px 초과 → 중단(드래그 스크롤과의 충돌 규칙도
  현행 `PRESS_CANCEL_DISTANCE=10px` 그대로).
- **행 순서 불변** — 레시피는 `recipes.csv` 선언 순서 고정(반복 제작 중 줄이
  흔들리면 안 된다). 카테고리 묶음 안에서도 선언 순서.
- 제작 결과 반영은 지금처럼 `player` 참조 교체 → 재렌더(React 구독이 자연 처리).

## 3. 결정 2 — 분류는 데이터가 소유한다 (`category` 칼럼)

- `recipes.csv`에 `category` 칼럼 추가. 초기값: `제련`(구리 주괴), `도구`(나머지 5).
  제작 패널은 카테고리 섹션 헤더 아래 레시피 카드를 묶는다. 원작 콘텐츠를 확장하며
  `소모품`·`장신구` 같은 칸이 늘어나는 자리다.
- `items.csv`에는 칼럼을 **추가하지 않는다** — 가방의 섹션은 이미 있는
  `kind`(도구/재료)로 나눈다. 18개 아이템에 그 이상의 세분류는 지금 필요가 없고,
  필요해지는 날 레시피와 같은 방식으로 추가하면 된다(YAGNI).
- 검증(`validate.ts`): category 는 빈 값 금지. 같은 카테고리 이름의 표기 흔들림
  (`도구`/`도구 `)은 trim 으로 흡수. 카테고리 등장 순서 = CSV 에서 처음 나타난 순서.

## 4. 결정 3 — 아이콘 체계: 전용 배정 + 매니페스트 대조 테스트

- **18개 아이템 전부에 전용 아이콘을 배정한다.** Time Fantasy 1023장에서 고른다.
  빌려 쓰던 6개(얼음 2, 약초 2 등)는 재배정하고, 도구는 종류별로 구분되는 그림
  (정·도끼·곡괭이·낫·망치)에 재질(구리/철)별 변형을 고른다 — 같은 그림 돌려쓰기 금지.
- 고르는 절차: 팩의 `quick_guide.png`·통합 시트를 **내가 직접 눈으로 보고** 번호를
  고른다(맵 렌더 승인과 같은 규칙). 고른 결과는 CREDITS.md 의 기존 아이콘 레시피
  (번호→이름 표 + 복원 스크립트 heredoc)에 추가한다.
- **오탈자 안전망(새로 만든다):** 아이콘 PNG 는 gitignore 대상이라 빌드/CI 는 파일
  존재를 검사할 수 없다. 대신 `playerSprites.test.ts` 전례를 따라 커밋되는 매니페스트
  하나를 둔다 — `apps/client/src/game/itemIcons.ts`: 사용 가능한 아이콘 id 목록.
  테스트가 3자 대조한다: `items.csv`의 icon 값 ⊆ 매니페스트, 매니페스트 ⊆ CREDITS
  복원 스크립트의 이름 목록. 지금은 "런타임에 조용히 빈 칸"인 실패가 테스트 실패가 된다.
- `ItemIcon.tsx`(죽은 코드)를 이 작업의 공용 컴포넌트로 살린다. 로드 실패 시 조용히
  숨기는 현행 동작은 "이름 텍스트는 남는다"를 전제로 유지.

## 5. 가방 패널 (신설)

```
┌ 가방 ──────────────────────── ✕ ┐
│ 도구                              │
│ [🪓] 구리 도끼      착용 중       │
│ [⛏] 구리 곡괭이                  │
│ 재료                              │
│ [🧊] 얼음 조각 ×12  [🌿] 흔한 약초 ×3 │
│ [🪵] 무른 통나무 ×7  …            │
└──────────────────────────────────┘
```

- **도구 섹션**: `instances` 를 한 줄 카드(아이콘+이름+상태)로. 착용 중(`equipped`
  값과 instanceId 일치)이면 `착용 중` 배지(`--c-accent`). 강화(`enhanceLevel`)는
  0 이 아닐 때만 `+N` 으로 표기(지금은 전부 0 — 자리만 잡는다).
- **재료 섹션**: `stacks` 를 아이콘+이름+`×수량` 그리드(2열)로. 수량 0 은 행 자체가
  없다(stacks 에 키가 없으므로 자연 소멸).
- 정렬: 도구는 `instances` 배열 순서(획득 순), 재료는 `items.csv` 선언 순서 —
  제작 반복 중 줄이 흔들리지 않는 것과 같은 이유로 고정 순서.
- 비었을 때: "가방이 비어 있다." 한 줄.
- **v1 은 보기 전용이다.** 도구를 탭해 수동 착용하는 기능은 서버 API(착용 변경)가
  없으므로 이번 범위 밖 — 강화 시스템과 함께 온다(훅: 카드가 이미 instanceId 를 안다).

## 6. 제작 패널 (재설계)

```
┌ 제작 ──────────────────────── ✕ ┐
│ 제련                              │
│ ┌ [🧱] 구리 주괴        성공 60% ┐ │
│ │ 구리 원석 2/2 ✓      [제작]   │ │
│ └───────────────────────────────┘ │
│ 도구                              │
│ ┌ [🔨] 구리 망치   조합 숙련도 180/200 ┐
│ │ 구리 주괴 0/2                  🔒 │
│ └───────────────────────────────┘ │
└──────────────────────────────────┘
```

- 카테고리 섹션 헤더(§3) 아래 레시피 카드. 카드 구성:
  - 1행: 산출물 아이콘 + 레시피 이름 + 우측 상태(성공률 `N%` / `재료 부족` /
    `조합 숙련도 현재/필요`).
  - 2행: 재료를 아이콘 없이 `이름 보유/필요` 칩으로, 충족은 `--c-success`·부족은
    `--c-danger` — 현행 색 규칙 유지.
- **잠긴 카드도 그대로 보인다** — 원작 장치 보존. 잠김은 흐림 처리 + 요구치 숫자.
  숨기지 않는다.
- 카드 전체가 버튼이다(현행 "행 전체 탭" 계약 유지). 누르고 있으면 반복(§2).
  잠김/재료 부족 카드는 눌러도 서버에 보내지 않는다(현행 `tryCraft` 게이트와 동일).
- 성공/실패 피드백: 카드 우측 상태 영역이 결과 순간 `성공!`/`실패` 로 1초 점멸
  (서버 응답의 `success` 사용). 캐릭터 머리 위 전역 피드백(`lastAction`)은 그대로 —
  패널이 화면을 덮어 안 보이던 것을 카드 안 피드백이 대신한다.

## 7. 헤더 — 이정표 티커를 빼고 맵 이름을 넣는다

- `TopBar.tsx`의 `describeNextMilestone` 티커를 **제거**하고 그 자리에
  `data.maps[player.location.mapId]?.name` 을 표시한다(둘 다 이미 스코프에 있어
  새 배관 불필요 — 조사로 확인).
- 이것은 단순 교체가 아니라 설계 복원이다: 다음 문턱을 상단에 상시 노출하는 것은
  "진행도로 열리는 이벤트를 숨겨 둔다"는 원작 동기부여 설계와 정면 충돌했다.
  문턱은 문(레시피 카드의 요구치)과 사람(NPC 대사)이 말한다 — 헤더가 아니라.
- `describeNextMilestone`·`nextMilestone` 사용처가 헤더뿐인지 확인 후, 헤더 전용
  코드만 제거(shared 의 이정표 계산은 서버 판정이 쓰므로 남는다).

## 8-앞. 깨끗한 세션 평가 반영 (규범 — 위 절과 충돌하면 이 절이 이긴다)

**상호작용 계약 (치명 2건의 교정)**

1. **홀드 반복은 해금되는 기능이다.** 쥔 반복 타이머는 `craftRepeatUnlocked`
   (crafting 10,000 이정표)가 참일 때만 arm 한다 — 탭 1회는 항상 허용. §2 의
   3줄 계약대로 구현하면 신규 플레이어가 1분차부터 반복을 얻어 원작의 첫
   동기부여 장치가 죽는다.
2. **반복 루프는 고정 타이머가 아니다.** rAF(≤50ms) 폴링 + 현행 세 게이트 전부:
   패널 전역 pending 하나(멀티터치로 두 카드를 쥐어도 요청 루프는 하나) ·
   `nextActionAt`(서버 간격은 숙련도에 따라 500→50ms로 준다 — 고정 타이머는
   고숙련을 스로틀하거나 거부 스팸을 만든다) · `canAffordCraft`.
3. **`성공!/실패` 1초 점멸 폐기.** 결과가 초당 2~5회 오는 화면에서 점멸은 상시
   플리커다. 대신 카드 안 누적 카운터 — 스토어에 `craftTally:
   Record<recipeId, {success, fail}>` (제작 패널이 열릴 때 리셋), 카드 2행 끝에
   `+37 · 실패 12` 누적 표기. 성공률은 점멸에 가려지지 않는 고정 슬롯.
4. **카드 1행에 산출물 보유 수량 `보유 N`을 추가한다** (`player.stacks[output]`).
   반복 200회 동안 시선이 쉴 곳은 올라가는 보유 숫자다 — 가방을 열어야만
   보이면 안 된다.
5. **`store.craft()`가 결과를 삼키는 문제**: 현행은 `Promise<void>` — §6/규범 3을
   위해 craft 액션이 `craftTally` 갱신까지 책임진다(성공 여부는 서버 응답
   `outcome.success`). 별도 반환값 변경은 불필요.

**패널 소유권 (치명 1건의 교정)**

6. **열림 상태의 주인은 스토어 하나다**: `openPanel: 'bag' | 'craft' | 'menu' | null`.
   `menu`도 이 값에 들어간다 — PanelScene 은 `'menu'` 구독자로 격하되고 자체
   `open` 필드의 권위를 잃는다. 상호배제는 값 하나라서 공짜다.
7. **입력 라우팅은 기존 applyInput 체인 한 곳에 남는다.** DOM 패널에는 키보드
   리스너를 두지 않는다 — I/C/ESC 전부 기존 InputHub → applyInput 경로가
   `openPanel`을 읽고 쓴다. 이래야 대사창 계약(대화 중 I/C 삼킴, B는 대사창
   우선, 대사창이 패널 위)이 그대로 산다. DOM ✕ 버튼과 상단바 톱니는 스토어
   액션만 부른다(톱니는 열려 있던 DOM 패널을 닫고 menu 를 연다).
8. **세계 잠금·컨트롤러 숨김은 Phaser 쪽 구독자 한 곳에서 계산한다**:
   `lockedBy.panel = (openPanel !== null)`, `setControllerVisible(openPanel === null)`.
   React 는 ControlScene 에 닿을 수 없고, 잠금 주인이 흩어지면 "먼저 닫는 쪽이
   잠금을 푸는" 버그가 부활한다. 구독자는 bind 시점 초기값에도 적용한다.
9. **`openPanel` 수명**: logout·401·연결 게이트 이탈 시 `null` 리셋
   (`confirmingDelete` 전례). 안 하면 재접속 후 새 hub 는 안 잠겼는데 DOM 패널만
   열려 있는 상태가 된다.
10. **스크롤 계약**: 카드에 `touch-action: none` 금지 — `pan-y` 유지, 네이티브
    스크롤 개시가 내는 `pointercancel`로 홀드 중단(10px 규칙과 별개로 브라우저
    슬롭이 홀드를 끊을 수 있음을 수용). 길게 누르기 콜아웃·선택·확대 억제는
    이미 전역 처리돼 있다(global.css, viewport) — 새로 할 일 없음.

**표시 세부 (원작 장치를 실제로 지키는 쪽으로)**

11. **잠긴 카드의 흐림은 아이콘·이름·재료까지만.** 숙련도 카운터(`180/200`)는
    풀 콘트라스트(`--c-accent`) + `font-variant-numeric: tabular-nums` — 주괴를
    반복하는 동안 옆 카드에서 실시간으로 오르는 그 숫자가 당근이다. 카드에서
    가장 밝은 것이 요구치 숫자여야 한다.
12. **오래 들여다보는 숫자는 16px 를 유지한다.** 16 격자는 Phaser 제약이 아니라
    폰트 자체 속성(unitsPerEm=16)이라 DOM 에서도 11~13px 은 획이 흐려진다 —
    §2 의 "격자 제약이 사라진다" 근거는 기각. 수량·요구치·누적 카운터는 16px,
    카드 높이 예산도 16px 기준으로: **카드 ≤72px 목표**(아이콘 32px 정수 배율),
    쥔 카드와 다음 잠긴 카드가 한 화면(목록 가용 ~250px)에 같이 보여야 한다.
13. **가방 행은 버튼이 아니다** — 제작 카드와 다른 문법(눌림 상태·테두리 강조
    없음)으로 그려 죽은 버튼으로 읽히지 않게 한다. 전체-빈 상태는 도달
    불가능하므로 삭제(신규 캐릭터도 도구 4종을 갖고 시작), 재료 섹션 전용 빈
    문구 "아직 모은 재료가 없다"만 둔다. 착용 배지는 유지하되 시각적으로
    조용하게(신규 캐릭터는 4줄 전부 착용 상태다).

**데이터 파이프라인 (검증 위치의 교정)**

14. **category 의 trim·필수 검사는 validate.ts 가 아니라 parse.ts 다** —
    `requireCell(...).trim()`. validate 는 값을 변형하지 않는 계층이고, 셀 trim
    은 공백 한 칸 셀이 requireCell 을 통과하는 구멍도 함께 막는다.
    `RecipeDef`(shared/types.ts)에 `category: string` 추가.
15. **카테고리 순서 계약은 빌드가 지키게 한다**: Record 삽입 순서는 정수형
    키(`"2"`)가 생기는 순간 JSON 왕복에서 조용히 깨진다 — 레시피/아이템 id 에
    정수형 금지 정규식 검사를 parse 에 추가.
16. **`itemIcons.ts` 매니페스트 폐기 — 2자 대조로.** 런타임 소비자가 0인 세 번째
    손동기화 사본을 만들지 않는다. 클라이언트 테스트가 `loadGameData()`의 icon
    값 ⊆ CREDITS.md 복원 heredoc(정규식 `/^([a-z_]+):(\d+)$/` 줄 파싱 — 부분
    문자열 검사는 접두사 오탐)을 대조한다. CREDITS 를 repoRoot 상대경로로 읽는
    전례는 playerSprites.test.ts 에 이미 있다.
17. **유일성 단언 추가** — 3자 대조(⊆)만으로는 성공 기준 3("같은 그림 금지")을
    검증 못 한다: (a) items 의 icon 값 Set 크기 = 아이템 수, (b) heredoc 번호
    Set 크기 = 이름 수.
18. **CREDITS.md 는 표만이 아니라 본문도 고친다** — "13종 수동 개명, 확장 계획
    없음" 문구가 18종 확장과 어긋난다. "수십 종까지는 수동 개명 유지, 수백 종
    시점에 팔레트 스왑" 으로 본문을 갱신.
19. 전제 수치 교정: 전용 그림이 없는 아이템은 6개가 아니라 **12개**(ore_mithril×2,
    ingot_mithril×2, pickaxe_copper×4, pickaxe_iron×4) + 의미가 어긋난 통나무
    2개(soft_log→plate_reinforced, hard_log→ingot_iron). 결론(전 재배정) 불변.

**헤더 (§7 의 잔존 코드 주장 교정)**

20. **`nextMilestone` 은 서버가 쓰지 않는다** — 서버 판정은 `newlyAchieved`만
    쓴다. 티커 제거와 함께 `nextMilestone`(shared/milestones.ts)과 그 테스트
    블록, 이를 근거로 단 주석들(types.ts 의 순서 주석 등)을 함께 지운다.
    `metricValue`·`milestoneRatio`·`achievedIds`는 이정표 탭이 쓰므로 남는다 —
    진행도 열람처는 이정표 탭 + 달성 알림으로 유지된다(상실 아님).

## 8. 무엇을 안 하는가 (훅만)

- 수동 착용/해제 API 와 가방에서의 착용 조작(§5 — 강화와 함께).
- 아이템 상세 팝업(설명 텍스트 칼럼 자체가 아직 없다).
- `menu` 패널(설정·상세 탭)의 DOM 이전 — bag/craft 가 안착한 뒤 같은 패턴으로.
- 판매/버리기/정렬 옵션. 소모품 사용(소모품 아이템이 아직 없다).
- 아이콘 대량 확장 전략(형태×재질 팔레트 스왑 — CREDITS 가 이미 예고, 수백 종
  시점의 일).

## 9. 성공 기준

1. 가방 버튼 → 내 도구(착용 표시)와 재료(수량)가 아이콘과 함께 보인다. 빈 가방도
   말이 된다.
2. 제작 버튼 → 카테고리 섹션 아래 카드가 보이고, 잠긴 레시피는 요구치 숫자와 함께
   흐리게 보인다. 카드를 누르고 있으면 반복 제작이 되고, 결과가 카드 안에서 보인다.
3. 18개 아이템 전부가 서로 구분되는 전용 아이콘을 갖는다 — 같은 그림을 쓰는 두
   아이템이 없다.
4. 상단바에 현재 맵 이름이 보이고, 맵을 이동하면 바뀐다. 이정표 티커는 없다.
5. `pnpm data:build && pnpm test && pnpm typecheck` 초록 + 아이콘 3자 대조
   테스트가 CSV 오탈자를 잡는다는 것을 RED 로 증명.
6. 브라우저(812×375)에서 가방·제작·헤더를 실관찰 — 새 에셋 복원 절차(CREDITS)를
   수행한 PC 에서 아이콘이 실제로 그려진다.
